Описание ТБП59: "Оценить доказательства по делу" TO BE

|  |  |
| --- | --- |
| **Наименование процесса** | ТБП59. Оценить доказательства по делу |
| **Суть процесса** | Судья/тройка судей осуществляет оценку представленных по делу доказательств с поддержкой системы: первичные проверки доказательства, принятие решения о приобщении либо отказе в приобщении, при необходимости - проверка расчетов сумм, оценка доказательств в совокупности и достаточности, фиксация обоснований отклонения/недостающих доказательств и сохранение результатов для последующего использования в судебном акте. |
| **Участники процесса** | Судья/Тройка судей; Секретарь СЗ/Помощник судьи; Система |
| **НПА** | "Арбитражный процессуальный кодекс Российской Федерации" от 24.07.2002 № 95-ФЗ  Постановление Пленума Верховного Суда РФ от 23.12.2021 N 46 "О применении Арбитражного процессуального кодекса Российской Федерации при рассмотрении дел в суде первой инстанции" |

| **Ожидаемый результат** | Сформирован протокол первичных проверок доказательства и уведомление о необходимости действий; протокол передан в ТБП139 для валидации; в материалах дела зафиксирован статус проверки. |
| **Рекомендованная функциональность** | Распознавание текста и реквизитов (OCR); извлечение сущностей и атрибутов; контроль формальных признаков (читабельность, целостность, наличие обязательных реквизитов); формирование протокола проверки и версионирование; уведомление о готовности протокола; журналирование действий и ошибок; передача результата в ТБП139. |
| **Критичность** | необходимая |
| **Триггер** | Возникла необходимость оценить представленное по делу доказательство. |
| **Предварительные условия** | Доказательство размещено в материалах дела; пользователю предоставлен доступ к делу; сервисы распознавания/анализа доступны. |
| **Основной сценарий** | Судья выбирает доказательство в материалах дела и инициирует проверку. Система выполняет извлечение текста/реквизитов и формирует структурированное представление доказательства (карточку). Система проводит первичные проверки: формальные признаки, относимость к предмету спора, допустимость и признаки достоверности; фиксирует ограничения анализа (если имеются). Система формирует проект протокола первичных проверок, прикладывает его к материалам дела и уведомляет судью о готовности. Судья знакомится с протоколом и направляет его в ТБП139 для валидации (подтверждения либо корректировки выводов). |
| **Расширение (альтернативный сценарий)** | Если качество изображения/скана не позволяет извлечь часть данных, система формирует протокол с отметкой о невозможности автоматической проверки отдельных фрагментов и перечнем проблемных мест.  При недоступности сервисов обработки система фиксирует ошибку, выполняет повторную попытку по регламенту и отображает судье статус «ожидает обработки/ошибка обработки».  Если судья отменяет проверку до передачи в ТБП139, система сохраняет черновик протокола (при наличии) без передачи на валидацию. |

UC-002: Отказ в приобщении доказательства к материалам дела

|  |  |
| --- | --- |
| **Поле** | **Значение** |
| **№ шага процесса** | 7–9 |
| **Выполняемая задача** | Принять решение об относимости доказательства к делу; при отрицательном решении оформить и зафиксировать отказ в приобщении доказательства к материалам дела (с отражением в протоколе СЗ). |
| **Цель** | Обеспечить процессуальную фиксацию отказа в приобщении доказательства и завершить соответствующий сценарий в пределах процесса. |
| **Роль (в соответствии со схемой)** | Судья/Тройка судей; Система. При оформлении протокола СЗ: Секретарь СЗ/Помощник судьи. |
| **Ожидаемый результат** | В материалах дела сохранена запись об отказе в приобщении доказательства; отказ отражён в протоколе/журнале действий; дальнейшая обработка данного доказательства в рамках процесса прекращена. |
| **Рекомендованная функциональность** | Фиксация решения по развилке; ввод/выбор основания отказа и краткой мотивировки; формирование проекта записи об отказе по шаблону; контроль заполнения реквизитов; сохранение записи в карточке дела; поддержка внесения отказа в протокол СЗ (в т.ч. с валидацией секретарём/помощником); журналирование и контроль прав доступа. |
| **Критичность** | необходимая |
| **Триггер** | По итогам первичных проверок судья рассматривает вопрос относимости доказательства к делу. |
| **Предварительные условия** | Результаты первичных проверок доступны судье; судья авторизован; дело открыто в системе. |
| **Основной сценарий** | Судья рассматривает результаты первичных проверок и принимает решение по вопросу относимости доказательства. При решении «не относится» система открывает форму оформления отказа в приобщении. Судья указывает основание и (при необходимости) дополняет мотивировку отказа. Система формирует проект записи об отказе и сохраняет его в материалах дела. Секретарь СЗ/помощник судьи (при оформлении протокола СЗ) заносит отказ в протокол, при необходимости валидируя предложенные системой формулировки и реквизиты; система фиксирует действие в журнале. |
| **Расширение (альтернативный сценарий)** | Если судья меняет решение до сохранения записи, система отменяет подготовленную запись и возвращает пользователя к выбору решения по относимости.  При ошибке сохранения система выполняет повторную попытку и отображает пользователю статус сохранения; при повторном неуспехе — фиксирует инцидент и оставляет запись в состоянии «не сохранено». |

UC-003: Проверка расчетов сумм, указанных в документах (включая валидацию пользователем)

|  |  |
| --- | --- |
| **Поле** | **Значение** |
| **№ шага процесса** | 10–15 |
| **Выполняемая задача** | При необходимости выполнить проверку расчётов сумм, указанных в документах; сформировать протокол проверки расчётов и передать результаты на подтверждение (валидацию) в типовой процесс ТБП139. |
| **Цель** | Снизить риск арифметических ошибок и обеспечить судье проверяемый результат расчётов с возможностью подтверждения либо корректировки. |
| **Роль (в соответствии со схемой)** | Судья/Тройка судей; Система |
| **Ожидаемый результат** | Сформирован протокол проверки расчётов (исходные данные, формулы, итоги, выявленные расхождения); судья ознакомился с результатом; протокол передан в ТБП139 для валидации; в материалах дела зафиксирован статус проверки. |
| **Рекомендованная функциональность** | Извлечение числовых данных из документов (OCR/структурирование); модуль пересчёта и проверки формул; сопоставление сумм по связанным документам (при наличии); формирование протокола расчётов и версионирование; уведомление о готовности; передача результата в ТБП139; журналирование. |
| **Критичность** | необходимая |
| **Триггер** | Судья установил необходимость проверки расчетов сумм, указанных в документах по делу. |
| **Предварительные условия** | Документы с расчетами доступны; средства извлечения данных и расчетный модуль доступны; судья авторизован. |
| **Основной сценарий** | Судья определяет, требуется ли проверка расчётов, и при необходимости инициирует её. Система извлекает числовые значения и исходные параметры расчёта из представленных документов. Система выполняет пересчёт, фиксирует расхождения и формирует протокол проверки расчётов. Судья проверяет результаты, при необходимости уточняет исходные данные/подтверждает выбранный вариант расчёта. Судья направляет протокол в ТБП139 для валидации (подтверждения либо корректировки). |
| **Расширение (альтернативный сценарий)** | Если часть исходных данных не извлечена, система отмечает это в протоколе и предлагает судье указать значения вручную либо оставить без проверки соответствующий фрагмент.  При выявлении неоднозначности (несколько вариантов трактовки формулы/параметров) система фиксирует варианты в протоколе и требует выбора/уточнения при валидации.  При техническом сбое пересчёта система выполняет повторную попытку и фиксирует причину сбоя в журнале. |

UC-004: Оценка доказательств (включая фиксацию обоснований и сохранение данных)

|  |  |
| --- | --- |
| **Поле** | **Значение** |
| **№ шага процесса** | 16–29 |
| **Выполняемая задача** | Выполнить итоговую оценку доказательств по делу с использованием аналитических подсказок системы: определить достаточность доказательств, оценить их в совокупности, выявить неустановленные обстоятельства и недостающие доказательства, указать основания отклонения доказательств/доводов, сохранить результаты для последующего использования в СА. |
| **Цель** | Сформировать и сохранить в системе структурированные результаты оценки доказательств, пригодные для подготовки судебного акта и дальнейшего использования в подсистеме судебной аналитики. |
| **Роль (в соответствии со схемой)** | Судья/Тройка судей; Система |
| **Ожидаемый результат** | В системе сохранены: вывод о достаточности доказательств, результаты оценки в совокупности (включая взаимосвязи/противоречия), перечень неустановленных обстоятельств и недостающих доказательств (при наличии), основания отклонения доказательств/доводов; данные сохранены в виде, пригодном для повторного использования и подготовки судебного акта. |
| **Рекомендованная функциональность** | Формы ввода и структурирования выводов судьи; аналитические подсказки по достаточности/полноте и взаимосвязям доказательств; фиксация перечней недостающих доказательств и неустановленных обстоятельств; рекомендации по отражению обстоятельств; выбор оснований отклонения из справочника с возможностью уточнения; хранение результатов с версионированием и журналированием; контроль целостности и прав доступа; выгрузка/передача данных для использования в СА. |
| **Критичность** | необходимая |
| **Триггер** | Завершены первичные проверки доказательства и, при необходимости, проверка расчетов; требуется итоговая оценка доказательств по делу. |
| **Предварительные условия** | Доступны результаты проверок; судья авторизован; в системе доступна форма фиксации обстоятельств и оснований. |
| **Основной сценарий** | Система формирует предварительные подсказки по достаточности доказательств и полноте доказательственной базы (на основе имеющихся материалов). Судья выполняет оценку достаточности доказательств по предмету доказывания, подтверждая либо корректируя выводы системы. Если доказательств недостаточно, система предлагает зафиксировать недостающие доказательства и связанные неустановленные обстоятельства; судья подтверждает/уточняет перечень. Система анализирует взаимосвязи между доказательствами и отмечает противоречия/согласованность; судья оценивает доказательства в совокупности и при необходимости дополняет взаимосвязи. При необходимости система предлагает варианты оснований отклонения доказательств/доводов; судья выбирает и при необходимости уточняет формулировки. Система сохраняет результаты оценки в материалах дела и формирует структурированный набор данных для дальнейшего использования в СА. Судья завершает оценку доказательств по делу (фиксируется итоговый статус). |
| **Расширение (альтернативный сценарий)** | Если в ходе совокупной оценки требуется уточнение перечня недостающих доказательств, судья корректирует перечень до сохранения итогового результата; система сохраняет изменения с версией.  При попытке сохранить результат при отсутствии обязательных реквизитов (например, не заполнено основание отклонения при выборе соответствующего варианта) система блокирует сохранение и отображает перечень обязательных полей.  При ошибке сохранения система выполняет повторную попытку; при неуспехе фиксирует инцидент и сохраняет результат в статусе «не сохранено». |
