# [To be] ОБП14. Организация текущего обслуживания установленного в суде оборудования и техники

|  |  |
| --- | --- |
| **Наименование процесса** | ОБП14 — Организация текущего обслуживания установленного в суде оборудования и техники |
| **Суть процесса** | Процесс охватывает организацию и проведение текущего технического обслуживания оборудования и техники, установленных в суде. Он начинается при возникновении потребности в таком обслуживании. Внутри процесса отдел информатизации проводит инвентаризацию, составляет график технического обслуживания и уведомляет пользователей о предстоящих работах. Далее обслуживание выполняется либо силами отдела информатизации, либо с привлечением подрядчика с последующим ознакомлением с результатами и подписанием документов. Процесс завершается регистрацией результатов обслуживания, уведомлением пользователей и их ознакомлением с итогами проведенных работ. |
| **Участники процесса** | Отдел информатизации  Пользователи  Подрядчик  Система |
| **НПА** | Федеральный закон от 27.07.2006 N 149-ФЗ "Об информации, информационных технологиях и о защите информации"  Федеральный закон от 29.12.2022 N 584-ФЗ "О внесении изменений в Федеральный закон «Об информации, информационных технологиях и о защите информации»"  Федеральный закон от 05.04.2013 N 44-ФЗ "О контрактной системе в сфере закупок товаров, работ, услуг для обеспечения государственных и муниципальных нужд" |

**UC-01. Сформировать график технического обслуживания оборудования и техники**

|  |  |
| --- | --- |
| **№ шага процесса** | 1–9 |
| **Выполняемая задача** | Сформировать график технического обслуживания оборудования и техники |
| **Цель** | Определить состав оборудования и техники, требующих обслуживания, сформировать актуальный график работ и уведомить пользователей о предстоящем техническом обслуживании. |
| **Роль/Актор (в соответствии со схемой)** | Основной актор: Отдел информатизации.  Дополнительные акторы: Система; Пользователи. |
| **Ожидаемый результат** | В Системе создана сущность обслуживания, проведена инвентаризация, сформирован график технического обслуживания, пользователи уведомлены о предстоящих работах. |
| **Рекомендованная функциональность** | Создание и ведение сущности технического обслуживания; запуск автоматизированной проверки перечня оборудования; формирование рекомендаций на основании сведений о предыдущих заявках и обслуживании; передача выводов на пользовательскую проверку; регистрация результатов инвентаризации и акта; автоматическое формирование и хранение графика; формирование и направление уведомлений пользователям; фиксация ознакомления с уведомлением. |
| **Критичность\*** | Необходимая |
| **Триггер** | Появилась потребность в обслуживании установленного в суде оборудования и техники. |
| **Предварительные условия** | В Системе доступны сведения об установленном оборудовании и технике, а также данные о ранее выполненном обслуживании и поступавших заявках. |
| **Основной сценарий** | 1. Сотрудник отдела информатизации создает в Системе сущность обслуживания.  2. Сотрудник запускает проверку списка оборудования и техники.  3. Система анализирует имеющиеся сведения, заполняет сущность и формирует рекомендацию по объектам, требующим обслуживания.  4. Сотрудник проверяет выводы Системы  5. Сотрудник   фиксирует  результаты инвентаризации в акте.  6. Сотрудник запускает формирование графика технического обслуживания.  7. Система создает график и связывает его с сущностью обслуживания.  8. Отдел информатизации уведомляет пользователей о предстоящих работах.  9. Пользователи знакомятся с уведомлением. |
| **Расширение (альтернативный сценарий)** | 3а. Если Система не может сформировать рекомендацию из-за недостаточности или противоречивости данных, сотрудник уточняет сведения об оборудовании и повторно запускает проверку.  4а. Если выводы Системы признаны некорректными, сотрудник корректирует состав оборудования и сведения, используемые при формировании графика.  5а. Если при инвентаризации выявлено неучтенное либо выбывшее оборудование, сведения в Системе актуализируются до формирования графика. |

**UC-02. Выполнить техническое обслуживание оборудования и техники**

|  |  |
| --- | --- |
| **№ шага процесса** | 10–16 |
| **Выполняемая задача** | Выполнить техническое обслуживание оборудования и техники |
| **Цель** | Обеспечить проведение запланированных работ по техническому обслуживанию самостоятельно либо с привлечением подрядчика и зафиксировать документы, подтверждающие их выполнение. |
| **Роль/Актор (в соответствии со схемой)** | Основной актор: Отдел информатизации.  Дополнительные акторы: Система; Подрядчик — внешний участник, выполняющий работы вне пула суда. |
| **Ожидаемый результат** | Техническое обслуживание выполнено одним из предусмотренных способов; при привлечении подрядчика результаты работ проверены, документы подписаны и сохранены в Системе вместе с открепленной электронной подписью. |
| **Рекомендованная функциональность** | Выбор способа выполнения обслуживания; формирование запроса подрядчику на основании графика; регистрация факта направления запроса; загрузка уведомления и документов о выполненных работах; просмотр и проверка результатов обслуживания; подписание документов электронной подписью; автоматическое сохранение подписанного документа и открепленной электронной подписи в сущности обслуживания; фиксация самостоятельного выполнения работ. |
| **Критичность\*** | Необходимая |
| **Триггер** | Наступил срок технического обслуживания согласно сформированному графику. |
| **Предварительные условия** | Сформирован график технического обслуживания; определен перечень оборудования и техники; пользователи уведомлены о предстоящих работах; определен способ выполнения обслуживания. |
| **Основной сценарий** | 1. Отдел информатизации определяет, что обслуживание выполняется самостоятельно.  2. Сотрудник отдела информатизации проводит необходимые работы с оборудованием и техникой.  3. Ветвь самостоятельного обслуживания завершается и процесс переходит к регистрации результатов. |
| **Расширение (альтернативный сценарий)** | 1а. Если обслуживание выполняется подрядчиком, сотрудник формирует на основании графика запрос на техническое обслуживание и направляет его подрядчику.  2а. После выполнения работ сотрудник получает уведомление и документы о выполнении технического обслуживания.  3а. Сотрудник знакомится с результатами работ и проверяет документы.  4а. При отсутствии замечаний сотрудник подписывает документы.  5а. Система сохраняет подписанный документ и открепленную электронную подпись в сущности обслуживания.  3б. Если выявлены недостатки работ или документов, материалы возвращаются подрядчику для устранения замечаний; после повторного поступления проверка выполняется заново. |

**UC-03. Зарегистрировать результаты технического обслуживания и уведомить пользователей**

|  |  |
| --- | --- |
| **№ шага процесса** | 17–20 |
| **Выполняемая задача** | Зарегистрировать результаты технического обслуживания и уведомить пользователей |
| **Цель** | Зафиксировать итоги выполненного обслуживания в Системе и довести информацию о результатах работ до пользователей оборудования и техники. |
| **Роль/Актор (в соответствии со схемой)** | Основной актор: Отдел информатизации.  Дополнительный актор: Пользователи. |
| **Ожидаемый результат** | Результаты технического обслуживания зарегистрированы в Системе; пользователям направлено уведомление; факт ознакомления пользователей зафиксирован; процесс завершен. |
| **Рекомендованная функциональность** | Регистрация результатов обслуживания в привязке к сущности, графику и конкретному оборудованию; внесение сведений о выполненных работах, исполнителе и дате; прикрепление подтверждающих документов; изменение статуса обслуживания; формирование и массовая отправка уведомлений; фиксация доставки и ознакомления; хранение истории обслуживания оборудования. |
| **Критичность\*** | Необходимая |
| **Триггер** | Техническое обслуживание выполнено самостоятельно либо завершено подрядчиком, а необходимые документы сохранены в Системе. |
| **Предварительные условия** | Работы по техническому обслуживанию завершены; сведения и подтверждающие документы доступны сотруднику отдела информатизации. |
| **Основной сценарий** | 1. Сотрудник отдела информатизации регистрирует в Системе результаты технического обслуживания.  2. Система связывает результаты с сущностью обслуживания и соответствующим оборудованием.  3. Сотрудник формирует и направляет пользователям уведомление о результатах работ.  4. Пользователи получают уведомление и знакомятся с результатами.  5. В Системе фиксируется завершение текущего обслуживания оборудования и техники. |
| **Расширение (альтернативный сценарий)** | 1а. Если для регистрации недостаточно сведений или документов, Система не позволяет завершить обслуживание и указывает незаполненные обязательные поля.  3а. Если уведомление не доставлено отдельным пользователям, Система фиксирует ошибку доставки и предоставляет возможность повторного направления. |
