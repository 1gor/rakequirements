| **Наименование процесса** | ОБП33 — Информационная и программная поддержка применяемых в суде автоматизированных процессов |
| --- | --- |
| **Суть процесса** | Обеспечение работоспособности информационных систем суда посредством автоматизированного контроля заявок и состояния ИС, проверки выявленных сбоев и организации их устранения собственными силами либо с привлечением подрядчика. |
| **Участники процесса** | Отдел информатизации; Подрядчик; Система |
| **НПА** | Федеральный закон от 27.07.2006 № 149-ФЗ «Об информации, информационных технологиях и о защите информации»  Федеральный закон от 08.01.1998 № 7-ФЗ «О Судебном департаменте при Верховном Суде Российской Федерации»  Приказ Судебного департамента при Верховном Суде РФ от 25.03.2015 № 82 «Об утверждении Положения об Управлении информатизации Судебного департамента при Верховном Суде Российской Федерации» |

## **3. Реестр UC**

**UC001 — Проверить заявки и выявить инцидент в работе ИС**

| **№ шага процесса** | 0–11, 19–20 |
| --- | --- |
| **Выполняемая задача** | Автоматическая проверка заявок и работоспособности информационной системы, формирование отчета, уведомление ответственного сотрудника и проверка выводов Системы. |
| **Цель** | Выявить обращения и технические сбои, проверить корректность автоматических выводов и определить необходимость устранения подтвержденного инцидента. |
| **Роль/Актор (в соответствии со схемой)** | Основной актор: Отдел информатизации. Участник: Система. |
| **Ожидаемый результат** | Сформирован и проверен отчет по заявкам, результатам мониторинга и ошибкам; подтверждено наличие сбоя и определена необходимость его устранения либо установлено, что сбой отсутствует. |
| **Рекомендованная функциональность** | Автоматическая проверка реестра заявок; автоматический мониторинг доступности и работоспособности ИС; анализ технических показателей и журналов событий; автоматическое определение вероятной причины сбоя; формирование сводного отчета; уведомление ответственного сотрудника; предоставление доступа к отчету; вызов ТБП139 для проверки выводов Системы. |
| **Критичность** | Необходимая. |
| **Триггер** | Возникла необходимость проверить заявки на поддержку и работоспособность информационной системы суда. |
| **Предварительные условия** | Системе доступны реестр заявок, технические показатели и журналы событий ИС; определен ответственный сотрудник или группа сотрудников отдела информатизации. |
| **Основной сценарий** | 1. Возникает необходимость оказания информационной и программной поддержки информационной системы суда.  2. Система запускает одну или обе ветви первичной проверки состояния ИС.  3. Система автоматически проверяет наличие заявок сотрудников судов и формирует перечень обращений, относящихся к поддержке автоматизированных процессов.  4. Система автоматически выполняет мониторинг доступности и работоспособности ИС на основании технических показателей и журналов событий.  5. После завершения проверок результаты объединяются.  6. По результатам проверки определяется наличие признаков сбоя в работе ИС.  7. При обнаружении сбоя Система анализирует результаты мониторинга и журналы ошибок и формирует вывод о его вероятной причине.  8. Система формирует сводный отчет по заявкам, результатам мониторинга и выявленным ошибкам.  9. Система уведомляет ответственного сотрудника или группу сотрудников отдела информатизации и предоставляет доступ к отчету.  10. Специалист отдела информатизации выполняет ТБП139 «Проверить выводы системы».  11. Специалист отдела информатизации подтверждает наличие сбоя в работе ИС.  12. Процесс переходит к UC002 «Устранить подтвержденный сбой в работе ИС». |
| **Расширение (альтернативный сценарий)** | 6а. По результатам автоматической проверки признаки сбоя не обнаружены.  6а.1 Система формирует отчет по проверенным заявкам и результатам мониторинга без указания подтвержденного сбоя.  6а.2 Специалист отдела информатизации проверяет выводы Системы.  6а.3 Процесс завершается с результатом «Информационная и программная поддержка ИС оказана».  11а. По результатам ТБП139 специалист отдела информатизации не подтверждает наличие сбоя.  11а.1 Дополнительные действия по устранению инцидента не выполняются.  11а.2 Процесс завершается с результатом «Информационная и программная поддержка ИС оказана». |

**UC002 — Устранить подтвержденный сбой в работе ИС**

| **№ шага процесса** | 12–20 |
| --- | --- |
| **Выполняемая задача** | Определение способа устранения подтвержденного сбоя, восстановление работоспособности ИС силами отдела информатизации либо с привлечением подрядчика и контроль результата. |
| **Цель** | Устранить подтвержденный сбой и восстановить доступность и корректную работу затронутых компонентов информационной системы. |
| **Роль/Актор (в соответствии со схемой)** | Основной актор: Отдел информатизации. Участник: Подрядчик. |
| **Ожидаемый результат** | Сбой устранен собственными силами либо подрядчиком; результат подтвержден проверкой; информационная и программная поддержка ИС оказана. |
| **Рекомендованная функциональность** | Фиксация решения о способе устранения сбоя; формирование и направление запроса подрядчику; регистрация сообщения подрядчика о выполнении работ; фиксация результатов повторной проверки; поддержка повторного направления запроса подрядчику; регистрация самостоятельного устранения сбоя и завершения обработки инцидента. |
| **Критичность** | Необходимая. |
| **Триггер** | Специалист отдела информатизации подтвердил наличие сбоя в работе ИС по результатам проверки выводов Системы. |
| **Предварительные условия** | Сформирован и проверен отчет об ошибках и обращениях; причина сбоя определена либо имеются достаточные сведения для выбора способа его устранения. |
| **Основной сценарий** | 1. Специалист отдела информатизации определяет, требуется ли привлечение подрядчика для устранения подтвержденного сбоя.  2. Если подрядчик требуется, отдел информатизации направляет ему запрос со сведениями, необходимыми для выполнения работ.  3. Отдел информатизации ожидает сообщение подрядчика о результатах устранения сбоя.  4. После получения информации от подрядчика специалист отдела информатизации повторно проверяет доступность и корректность работы затронутых компонентов ИС.  5. По результатам повторной проверки определяется отсутствие сбоя.  6. Процесс завершается с результатом «Информационная и программная поддержка ИС оказана». |
| **Расширение (альтернативный сценарий)** | 1а. Для устранения сбоя не требуется привлечение подрядчика.  1а.1 Специалист отдела информатизации самостоятельно выполняет диагностику, настройку или восстановление компонентов ИС.  1а.2 После устранения сбоя процесс завершается с результатом «Информационная и программная поддержка ИС оказана».  5а.
