# [To be] ОБП46. Ведение номенклатуры дел

|  |  |

| Наименование процесса | ОБП46 — Ведение номенклатуры дел |
| Суть процесса | Формирование, проверка, согласование, утверждение, регистрация и публикация сводной номенклатуры дел арбитражного суда с использованием автоматизированной подготовки отдельных материалов и обязательной проверкой результатов пользователями. |

| НПА | Федеральный закон от 22.10.2004 № 125-ФЗ (ред. от 13.12.2024) «Об архивном деле в Российской Федерации»; Постановление Пленума ВАС РФ от 25.12.2013 № 100 (ред. от 11.07.2014) «Об утверждении Инструкции по делопроизводству в арбитражных судах Российской Федерации (первой, апелляционной и кассационной инстанций)» |

## ****3. Реестр UC****

**UC001 — Сформировать проект сводной номенклатуры дел**

|  |  |
| --- | --- |
| **№ шага процесса** | 0–8 |
| **Выполняемая задача** | Создание объекта сводной номенклатуры дел, определение сроков и ответственных лиц, включение заголовков дел подразделений, автоматизированное определение разделов и сроков хранения с последующей проверкой выводов Системы. |
| **Цель** | Подготовить полный и нормативно обоснованный проект сводной номенклатуры дел для дальнейшего согласования. |
| **Роль/Актор (в соответствии со схемой)** | Основной актор: Председатель суда. Участники: Руководители подразделений суда; Руководитель архива; Система. |
| **Ожидаемый результат** | Создана карточка сводной номенклатуры, определены сроки и ответственные лица, включены заголовки дел подразделений, сформированы разделы и сроки хранения, результаты автоматического анализа проверены руководителем архива. |
| **Рекомендованная функциональность** | Создание карточки сводной номенклатуры; фиксация сроков и ответственных лиц; сбор заголовков дел от подразделений; автоматическое определение разделов; анализ НПА; определение сроков хранения и номеров статей; вызов ТБП139 для проверки выводов Системы; хранение проекта и результатов проверки. |
| **Критичность** | Необходимая. |
| **Триггер** | Возникла необходимость составить сводную номенклатуру дел на соответствующий период. |
| **Предварительные условия** | Определен период, на который формируется сводная номенклатура; в Системе доступны сведения о структуре суда и подразделениях. |
| **Основной сценарий** | 1. Председатель суда создает в Системе новый объект сводной номенклатуры дел.  2. Председатель суда определяет сроки подготовки и утверждения номенклатуры.  3. Председатель суда определяет ответственных лиц за подготовку материалов и проекта документа.  4. Руководители подразделений суда включают в номенклатуру заголовки дел, отражающие документируемые участки работы подразделений.  5. Система автоматически определяет разделы номенклатуры по направлениям деятельности суда.  6. Система анализирует применимые нормативные правовые акты.  7. Система определяет сроки хранения дел и номера соответствующих статей по перечню.  8. Руководитель архива выполняет ТБП139 «Проверить выводы системы».  9. Проверенный проект сводной номенклатуры передается к подписанию и согласованию. |
| **Расширение (альтернативный сценарий)** | Не предусмотрен. |

**UC002 — Согласовать и утвердить сводную номенклатуру дел**

|  |  |
| --- | --- |
| **№ шага процесса** | 9–13 |
| **Выполняемая задача** | Подписание проекта сводной номенклатуры, его согласование экспертной комиссией и внешней экспертно-проверочной комиссией, последующее утверждение председателем суда. |
| **Цель** | Получить необходимые согласования и придать сводной номенклатуре дел утвержденный статус. |
| **Роль/Актор (в соответствии со схемой)** | Основной актор: Руководитель архива. Участники: Начальник отдела делопроизводства; Экспертная комиссия; Экспертно-проверочная комиссия уполномоченного органа субъекта Российской Федерации; Председатель суда; Система. |
| **Ожидаемый результат** | Проект подписан ответственными лицами, согласован экспертной комиссией и внешней экспертно-проверочной комиссией, после чего утвержден председателем суда. |
| **Рекомендованная функциональность** | Подписание проекта ответственными лицами; маршрутизация в экспертную комиссию; хранение протокола экспертной комиссии; получение протокола внешней экспертно-проверочной комиссии по интегрированному каналу; связывание протоколов с материалами процесса; фиксация утверждения председателем суда. |
| **Критичность** | Необходимая. |
| **Триггер** | Проект сводной номенклатуры сформирован, а результаты автоматического анализа проверены руководителем архива. |
| **Предварительные условия** | Проект сводной номенклатуры и разделы номенклатуры сформированы и доступны участникам согласования. |
| **Основной сценарий** | 1. Руководитель архива подписывает проект сводной номенклатуры после проверки выводов Системы.  2. Начальник отдела делопроизводства подписывает проект и передает его экспертной комиссии.  3. Экспертная комиссия рассматривает проект сводной номенклатуры.  4. Экспертная комиссия оформляет протокол и обеспечивает передачу проекта на внешнее согласование.  5. Система получает протокол экспертно-проверочной комиссии по интегрированному каналу.  6. Система связывает полученный протокол с материалами процесса.  7. Председатель суда утверждает согласованную сводную номенклатуру дел.  8. Утвержденный документ передается на регистрацию. |
| **Расширение (альтернативный сценарий)** | Не предусмотрен. |
