| Наименование процесса | ТБП1:Проверить явку в СЗ |
| Суть процесса | Процесс описывает проверку явки, происходящую как в ходе подготовки к СЗ/ПСЗ, так и в ходе непосредственно проведения назначенного СЗ/ПСЗ. В ходе процесса формируется список участников, происходит проверка явки извещенных лиц, а также фиксируются неявившиеся извещенные лица, отражаются сведения о причинах их неявки при наличии таких данных. Также проверяется наличие ходатайств от неявившихся лиц о рассмотрении дела без их участия, происходит контроль надлежащего уведомления участников, после чего помощник судьи/секретарь СЗ докладывает информацию о явке лиц судье. Процесс завершается фиксацией всех явившихся и неявившихся лиц. |
| Участники процесса | Помощник судьи, Секретарь судебного заседания, Судья |

* 1. Схема процесса
  2. Описание схемы процесса

| 0 | В ходе подготовки к СЗ/ПСЗ или в начале проведения СЗ/ПСЗ суд переходит к проверке явки участников процесса | Тип: Простое начальное событие Назначение: Перед началом судебного заседания инициируется проверка явки участников процесса. Проверка явки выполняется как обязательное процессуальное действие, предшествующее докладу судье о составе присутствующих и отсутствующих лиц. Статусы/маршрутизация: Карточка СЗ/ПСЗ: статус «Назначено» «Требуется проверка явки». Задача «Проверить явку участников»: начальный статус «Создана / К выполнению». Автоматизация: Тип: частично автоматизировано. Система создаёт задачу/напоминание о необходимости проверки явки к началу СЗ/ПСЗ. Пользователь принимает задачу к исполнению. Ранее контроль осуществлялся вручную. Результат: Создана задача «Проверить явку участников СЗ/ПСЗ»; карточка СЗ/ПСЗ переведена в состояние, допускающее выполнение проверки явки. Роль: Помощник судьи /секретарь СЗ Входящие данные: Отсутствуют Исходящие данные: Отсутствуют |  |
| 1 | Проанализировать материалы электронного дела | Тип: Сервисная задача Назначение: Система анализирует материалы электронного дела и извлекает сведения, необходимые для проверки явки: данные об участниках процесса, извещениях и поступивших ходатайствах. Полученные сведения используются на последующих шагах процесса. Статусы/маршрутизация: Задача «Проверить явку участников»: статус «В работе». Промежуточный результат: сведения из электронного дела подготовлены к анализу. Автоматизация: Тип: полностью автоматизировано. Система извлекает сведения об участниках из карточки дела. Ранее формировалось вручную. Результат: Из электронного дела получены исходные данные для проверки явки: сведения об участниках процесса, извещениях и поступивших ходатайствах. Роль: Система Входящие данные: Материалы электронного дела Исходящие данные: Отсутствуют |  |
| 2 | Сформировать список участников процесса | Тип: Сервисная задача Назначение: На основании данных электронного дела система формирует актуальный список участников процесса, подлежащих проверке перед началом судебного заседания. Сформированный список используется как основной рабочий перечень при фиксации явки и неявки. Статусы/маршрутизация: Промежуточный результат: список участников процесса сформирован. Статус объекта «Список участников»: «Сформирован». Автоматизация: Тип: полностью автоматизировано. Система формирует список участников. Ранее выполнялось вручную. Результат: Сформирован актуальный список участников процесса, подлежащих проверке перед началом СЗ/ПСЗ. Роль: Система Входящие данные: Отсутствуют Исходящие данные: Список участников процесса |  |
| 3 | Отметить неизвещённых в списке участников процесса | Тип: Сервисная задача Назначение: Система сопоставляет сведения об извещении с перечнем участников и отмечает лиц, в отношении которых отсутствует подтверждение надлежащего извещения. Эта информация далее учитывается при решении вопроса о возможности рассмотрения дела в отсутствие неявившихся лиц. Статусы/маршрутизация: Статусы участников в списке: «Извещён» / «Не извещён». Результат шага: для не извещённых лиц установлен признак «Требуется учёт при решении вопроса о возможности проведения СЗ/ПСЗ». Автоматизация: Тип: полностью автоматизировано. Система анализирует данные об извещениях и присваивает статус «извещён / не извещён». Ранее проверка выполнялась вручную. Результат: Для каждого участника в списке установлен статус извещения: «извещён» либо «не извещён». Роль: Система Входящие данные: Отсутствуют Исходящие данные: Отсутствуют |  |
| 4 | Проанализировать данные о регистрации участников процесса | Тип: Сервисная задача Назначение: Система получает и обрабатывает сведения о регистрации участников из СКУД и (или) QR-регистрации. Эти данные используются для определения явки участников к началу судебного заседания. Статусы/маршрутизация: Промежуточный результат: получены данные о регистрации. Статус проверки явки остаётся «В работе». Автоматизация: Тип: полностью автоматизировано. Система получает данные регистрации участников (СКУД/QR). Ранее фиксировалось вручную. Результат: Получены сведения из СКУД и/или QR-регистрации о регистрации участников к началу СЗ/ПСЗ. Роль: Система Входящие данные: Отсутствуют Исходящие данные: Отсутствуют |  |
| 5 | Зарегистрировались все участники процесса? | Тип: Развилка «ИЛИ/ИЛИ» Назначение: На основании сведений о регистрации и подтвержденной пользователем фактической явки процесс направляется либо к фиксации явившихся участников, либо к обработке сведений о неявившихся лицах. Шлюз выполняет маршрутизацию по уже установленному статусу явки. Статусы/маршрутизация: Шлюз маршрутизирует процесс по ранее установленному статусу фактической явки: «все участники явились» переход к фиксации явившихся; «есть неявившиеся участники» переход к фиксации неявки и причин отсутствия. Автоматизация: Тип: частично автоматизировано. Система использует ранее сформированные данные регистрации участников (СКУД/QR) и статус фактической явки, подтверждённый пользователем, и выполняет маршрутизацию процесса. Ранее маршрутизация выполнялась пользователем вручную. Результат: Маршрут процесса выбран по ранее установленному статусу фактической явки участников. Роль: Помощник судьи /секретарь СЗ Входящие данные: Отсутствуют Исходящие данные: Отсутствуют |  |
| 6 | Отметить зарегистрированных участников | Тип: Сервисная задача Назначение: Система фиксирует в перечне участников лиц, явившихся и зарегистрированных к началу судебного заседания. В результате формируется актуальный список присутствующих участников процесса. Статусы/маршрутизация: Статусы участников: «Явился / Зарегистрирован». Промежуточный результат: список явившихся сформирован. Автоматизация: Тип: полностью автоматизировано. Система фиксирует явку участников при регистрации. Ранее вручную. Результат: В системе зафиксирован перечень явившихся участников судебного заседания. Роль: Система Входящие данные: Отсутствуют Исходящие данные: Отсутствуют |  |
| 7 | Отметить незарегистрированных участников | Тип: Сервисная задача Назначение: Система фиксирует в перечне участников лиц, не прошедших регистрацию к началу судебного заседания. Эти сведения используются для дальнейшей работы с причинами неявки, ходатайствами и вопросом надлежащего извещения. Статусы/маршрутизация: Статусы участников: «Не явился / Не зарегистрирован». Промежуточный результат: список неявившихся сформирован. Автоматизация: Тип: полностью автоматизировано. Система определяет неявившихся по отсутствию регистрации. Ранее вручную. Результат: В системе зафиксирован перечень неявившихся участников судебного заседания. Роль: Система Входящие данные: Отсутствуют Исходящие данные: Отсутствуют |  |
| 8 | Проверить поступление данных о причинах неявки | Тип: Сервисная задача Назначение: Система выявляет сведения о причинах неявки по доступным данным и документам. Помощник судьи (секретарь СЗ) подтверждает наличие и достаточность этих сведений для последующей фиксации в системе. Статусы/маршрутизация: Результат проверки: «Есть сведения о причинах неявки» / «Сведения отсутствуют». Используется для последующего прохождения шлюза на шаге 9. Автоматизация: Тип: частично автоматизировано. Система автоматически выявляет наличие либо отсутствие сведений о причинах неявки из доступных данных и документов, после чего пользователь подтверждает наличие и достаточность этих сведений. Ранее выполнялось вручную. Результат: Установлено наличие либо отсутствие сведений о причинах неявки отсутствующих участников. Роль: Помощник судьи /секретарь СЗ Входящие данные: Отсутствуют Исходящие данные: Отсутствуют |  |
| 9 | Участник процесса предоставил сведения о причинах неявки? | Тип: Развилка «ИЛИ/ИЛИ» Назначение: В зависимости от ранее установленных сведений о причинах неявки процесс направляется либо к их отражению в системе, либо к дальнейшему движению без фиксации причин. Шлюз выполняет только маршрутизацию по уже полученным данным. Статусы/маршрутизация: Шлюз маршрутизирует процесс по ранее установленному статусу: «имеются сведения о причинах неявки» переход к их фиксации; «сведения о причинах неявки отсутствуют» переход к сходящейся развилке. Автоматизация: Тип: частично автоматизировано. Система использует ранее установленные сведения о причинах неявки и выполняет маршрутизацию процесса. Ранее выбор маршрута выполнялся пользователем вручную. Результат: Маршрут процесса выбран по ранее установленному статусу наличия сведений о причинах неявки. Роль: Помощник судьи /секретарь СЗ Входящие данные: Отсутствуют Исходящие данные: Отсутствуют |  |
| 10 | Отразить сведения о причинах неявки | Тип: Пользовательская задача Назначение: Помощник судьи (секретарь СЗ) вносит в систему известные причины неявки участников. Указанные сведения сохраняются в карточке судебного заседания и учитываются при докладе судье. Статусы/маршрутизация: Статусы участников: к статусу «Не явился» добавляется атрибут причины неявки («болезнь», «командировка», «ходатайство о рассмотрении в отсутствие» и др., если известно). Автоматизация: Тип: частично автоматизировано. Пользователь вносит и подтверждает сведения о причинах неявки, система сохраняет и структурирует данные. Результат: В системе сохранены известные причины неявки участников либо сведения об их отсутствии. Роль: Помощник судьи /секретарь СЗ Входящие данные: Отсутствуют Исходящие данные: Отсутствуют |  |
| 11 | Сходящаяся развилка | Тип: Сходящаяся развилка Назначение: После фиксации либо отсутствия сведений о причинах неявки процесс объединяется в единый поток. Это позволяет продолжить работу с общим набором данных о явке участников. Статусы/маршрутизация: Сходящаяся развилка: объединяет ветки «причина неявки отражена» и «причина неявки отсутствует». Статус задачи не меняется, остаётся «В работе». Автоматизация: Тип: полностью автоматизировано. Система объединяет ветки процесса без участия пользователя. Результат: Маршрут после обработки сведений о причинах неявки объединён в единый поток процесса. Роль: Помощник судьи /секретарь СЗ Входящие данные: Отсутствуют Исходящие данные: Отсутствуют |  |
| 12 | Сходящаяся развилка | Тип: Сходящаяся развилка Назначение: Результаты фиксации явки, неявки и причин отсутствия сводятся в единый маршрут процесса. Далее процесс переходит к работе с ходатайствами неявившихся участников. Статусы/маршрутизация: Сходящаяся развилка: объединяет результаты фиксации явки и неявки.
