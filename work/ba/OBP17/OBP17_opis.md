## ****3. Реестр UC****

### UC001 — Выявить и устранить сбой в работе систем и оборудования

|  |  |
| --- | --- |
| **№ шага процесса** | 0–16 |
| **Выполняемая задача** | Регистрация потребности в техническом обеспечении, автоматическое назначение исполнителя, диагностика оборудования и систем и устранение выявленного сбоя самостоятельно либо с привлечением подрядчика. |
| **Цель** | Выявить причину технического сбоя и обеспечить восстановление работоспособности информационных систем и оборудования суда. |
| **Роль/Актор (в соответствии со схемой)** | **Основной актор:** сотрудник отдела информатизации.**Участники:** Система; подрядчик. |
| **Ожидаемый результат** | Обращение зарегистрировано и назначено исполнителю; проведена диагностика; выявленный сбой устранён самостоятельно либо подрядчиком и результат устранения проверен. |
| **Рекомендованная функциональность** | Автоматическая регистрация технического обращения; автоматическое назначение исполнителя с учётом нагрузки; фиксация результатов проверки и диагностики; выбор способа устранения сбоя; формирование и направление заявки подрядчику; регистрация результатов работ подрядчика; работа с актом приёма-передачи; фиксация результата проверки устранения сбоя. |
| **Критичность** | Необходимая. |
| **Триггер** | Возникла необходимость организации технического обеспечения информационных систем или оборудования суда. |
| **Предварительные условия** | В Системе доступны сведения о сотрудниках отдела информатизации и их текущей нагрузке; имеется возможность зарегистрировать техническое обращение и назначить исполнителя. |
| **Основной сценарий** | 1. Система автоматически регистрирует возникшую потребность в техническом обеспечении. 2. Система назначает исполнителя с учётом текущей нагрузки сотрудников. 3. Сотрудник отдела информатизации проводит проверку оборудования и информационных систем. 4. По результатам проверки выявляется технический сбой. 5. Сотрудник анализирует причины сбоя и определяет способ его устранения. 6. Если привлечение подрядчика не требуется, сотрудник самостоятельно устраняет сбой. 7. Сотрудник проверяет результат выполненных мероприятий. 8. При успешном устранении сбоя процесс переходит к дальнейшему техническому обслуживанию и фиксации результата. |
| **Расширение (альтернативный сценарий)** | **4а. Сбой не обнаружен.** 4а.1 Процесс переходит к определению необходимости профилактического обслуживания в UC002. **6а. Требуется привлечение подрядчика.** 6а.1 Сотрудник проверяет наличие действующего договора на обслуживание. 6а.2 При отсутствии договора инициируется ОБП18 «Участвовать в госзакупках». 6а.3 После получения договорных оснований сотрудник формирует и направляет подрядчику заявку на устранение сбоя. 6а.4 После выполнения работ сотрудник знакомится с результатами и актом приёма-передачи. 6а.5 Сотрудник принимает выполненные работы и подписывает акт приёма-передачи. 6а.6 Выполняется проверка фактического устранения сбоя. **8а. Сбой не устранён.** 8а.1 Процесс возвращается к анализу причин сбоя и выбору дальнейшего способа устранения. |

| **Рекомендованная функциональность** | Фиксация решения о необходимости профилактического обслуживания; регистрация выполненных профилактических мероприятий; фиксация результатов контрольной проверки оборудования и систем; внесение итоговых сведений о техническом обслуживании в Систему; завершение технического обращения. |
| **Критичность** | Необходимая. |
| **Триггер** | Сбой успешно устранён либо по результатам первичной проверки технический сбой не обнаружен. |
| **Предварительные условия** | Проведена проверка оборудования и систем; при наличии сбоя выполнены необходимые мероприятия по его устранению. |
| **Основной сценарий** | 1. Сотрудник отдела информатизации определяет необходимость профилактического обслуживания. 2. Сотрудник проверяет корректность работы оборудования и систем после проведённых мероприятий. 4. Сотрудник вносит в Систему сведения о выполненных работах и результатах контрольной проверки. 5. Процесс завершается со статусом «Техническое обеспечение систем организовано». |
