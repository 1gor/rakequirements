|  |  |
| --- | --- |

## ****3. Реестр UC****

**UC001 — Предоставить сотруднику доступ к СПС**

|  |  |
| --- | --- |
| **№ шага процесса** | 0–13 |
| **Выполняемая задача** | Регистрация заявки на предоставление доступа к справочной правовой системе, назначение ответственных, предоставление учетных данных и организация обучения при необходимости. |
| **Цель** | Обеспечить сотруднику суда доступ к СПС и необходимые условия для начала работы с системой. |
| **Роль/Актор (в соответствии со схемой)** | Основной актор: сотрудник суда. Участники: отдел, ответственный за обеспечение доступа к СПС; Система. |
| **Ожидаемый результат** | Заявка обработана, сотруднику предоставлены необходимые учетные данные, при необходимости проведено обучение работе с СПС. |
| **Рекомендованная функциональность** | Создание и регистрация заявки; автоматическое создание сущности заявки; автоматическое назначение группы ответственных; фиксация принятия обращения в работу; сохранение сведений о предоставленных учетных данных; автоматическое уведомление сотрудника об изменениях по заявке; фиксация необходимости обучения и результатов его прохождения. |
| **Критичность** | Необходимая. |
| **Триггер** | У сотрудника суда возникла потребность в доступе к функциональности СПС. |
| **Предварительные условия** | Сотрудник суда зарегистрирован в Системе; определено подразделение, ответственное за обеспечение доступа к СПС. |
| **Основной сценарий** | 1. Сотрудник суда создаёт заявку на предоставление доступа к СПС.  2. Система автоматически создаёт сущность заявки и назначает ответственную группу.  3. Сотрудник ответственного отдела принимает обращение в работу.  4. Определяется необходимость предоставления новой учетной записи.  5. При необходимости сотруднику выдаются учетные данные для доступа к СПС.  6. Система сохраняет сведения о предоставленных данных в сущности заявки.  7. Система уведомляет сотрудника суда об изменении данных по заявке.  8. Определяется необходимость обучения сотрудника работе с СПС.  9. При необходимости организуется обучение и оформляется сертификат о его прохождении.  10. После предоставления доступа определяется наличие проблем при работе с СПС. |
| **Расширение (альтернативный сценарий)** | 4а. Сотрудник уже имеет необходимые учетные данные.  4а.1 Предоставление новой учетной записи не выполняется, процесс продолжается с уведомления сотрудника.  8а. Обучение работе с СПС не требуется.  8а.1 Процесс продолжается без проведения обучения.  10а. Проблемы при работе с СПС отсутствуют.  10а.1 Сотрудник переходит к работе с СПС, процесс завершается. |

**UC002 — Устранить проблему при работе с СПС**

|  |  |
| --- | --- |
| **№ шага процесса** | 14–24 |
| **Выполняемая задача** | Регистрация обращения в техническую поддержку, обработка и повторная обработка заявки при необходимости, закрытие обращения и уведомление инициатора о результате. |
| **Цель** | Восстановить корректную работу СПС и обеспечить сотруднику суда возможность продолжить использование системы. |
| **Роль/Актор (в соответствии со схемой)** | Основной актор: сотрудник суда. Участники: служба технической поддержки суда. |
| **Ожидаемый результат** | Проблема при работе с СПС устранена, заявка закрыта, сотрудник уведомлён о результате и может продолжить работу с системой. |
| **Рекомендованная функциональность** | Создание заявки в техническую поддержку; маршрутизация заявки; фиксация результатов обработки; повторная обработка обращения; изменение статуса заявки; закрытие заявки; направление уведомления инициатору о завершении работ. |
| **Критичность** | Необходимая. |
| **Триггер** | После предоставления доступа у сотрудника суда возникла проблема при работе с СПС. |
| **Предварительные условия** | Сотруднику суда предоставлен доступ к СПС; выявлена проблема, препятствующая корректной работе со справочной правовой системой. |
| **Основной сценарий** | 1. Сотрудник суда составляет заявку в техническую поддержку с описанием проблемы.  2. Сотрудник направляет заявку в службу технической поддержки суда.  3. Сотрудник технической поддержки обрабатывает обращение и выполняет необходимые действия по устранению проблемы.  4. Определяется результат обработки заявки.  5. При успешном устранении проблемы сотрудник технической поддержки закрывает заявку.  6. Инициатору направляется уведомление о завершении обработки обращения.  7. Сотрудник суда начинает или продолжает работу с СПС.  8. Процесс завершается со статусом «Обеспечено функционирование СПС». |
| **Расширение (альтернативный сценарий)** | 4а. Проблема не устранена после первичной обработки.  4а.1 Сотрудник технической поддержки повторно обрабатывает заявку и продолжает устранение проблемы.  4а.2 После успешного устранения процесс возвращается к закрытию заявки и уведомлению инициатора. |
