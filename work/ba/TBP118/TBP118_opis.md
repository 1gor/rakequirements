UC-003: Контроль надлежащего уведомления лиц

|  |  |
| --- | --- |
| Поле | Значение |
| № шага процесса | 11–14 (положительная ветка), 18–19 (негативная ветка) |
| Выполняемая задача | Запуск и выполнение контроля надлежащего уведомления (ТБП4), фиксация результата и выбор дальнейшего маршрута по результатам проверки. |
| Цель | Подтвердить надлежащее уведомление всех лиц, участвующих в деле, для возможности дальнейшего движения по выбранному порядку; при отсутствии уведомления обеспечить фиксацию негативного результата и продолжение по предусмотренному маршруту. |
| Роль | Судья |
| Ожидаемый результат | Проверка надлежащего уведомления выполнена и зафиксирована; по результату выбран маршрут; при положительном исходе фиксируется готовность дела к дальнейшему движению/рассмотрению, при негативном фиксируется негативный исход контроля уведомления в рамках заданной бизнес-логики. |
| Рекомендованная функциональность | Интеграции со статусами отправок/уведомлений; автоматическая сверка участников и адресов; контроль подтверждений вручения; уведомления судье о проблемах доставки; тайм-ауты/SLA и повторные попытки отправки; журналирование статусов; витрина «кто не уведомлён и почему»; автоматическое формирование задач на повторное извещение/уточнение данных. |
| Критичность | Высокая |
| Триггер | Судья нажимает действие «ТБП4. Контроль надлежащего уведомления» в карточке дела. |
| Предварительные условия | В системе отражены данные участников; доступны статусы уведомлений/подтверждения; доступ судьи к результатам контроля для валидации. |
| Основной сценарий | 1. Судья открывает карточку дела.  2. Система отображает действие «ТБП4. Контроль надлежащего уведомления».  3. Судья нажимает «ТБП4. Контроль надлежащего уведомления».  4. Система отображает результаты проверки уведомлений по всем участникам.  5. Судья выбирает результат «Все стороны извещены» и нажимает «Подтвердить».  6. Система сохраняет результат контроля и отображает статус готовности дела к дальнейшему движению/рассмотрению. |
| Альтернативные сценарии / расширения | 4а. Частичная доставка.  4а1. Система отображает детализацию статусов по каждому участнику.  4а2. Судья инициирует создание задачи на повторное уведомление/уточнение данных (если функциональность доступна).  4а3. Система создаёт задачу и отображает её в карточке дела.  5а. Не все стороны извещены (негативная ветка).  5а1. Судья выбирает результат «Не все стороны извещены» и нажимает «Подтвердить».  5а2. Система отображает перечень неуведомлённых лиц и причины.  5а3. Система сохраняет негативный результат и отображает признак движения по негативной ветке в рамках заданной бизнес-логики. |
