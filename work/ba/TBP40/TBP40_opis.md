# [To be] ТБП40. Рассмотреть заявление о возврате госпошлины

| **Наименование процесса** | ТБП40 — Рассмотреть заявление о возврате госпошлины |
| --- | --- |
| **Суть процесса** | Процесс предназначен для обработки заявления о возврате государственной пошлины. После поступления заявления Система автоматически выполняет поиск связанного дела. Если связанное дело не установлено, заявление передается в отдел делопроизводства, где Система проверяет формализуемые сведения заявления и документа, подтверждающего уплату государственной пошлины, и формирует протокол проверки. Сотрудник отдела делопроизводства проверяет результаты автоматической проверки и при необходимости корректирует фактические данные. По подтвержденным сведениям формируется и направляется заявителю справка о непоступлении искового заявления, иного заявления или жалобы в суд. Если связанное дело установлено, заявление регистрируется и передается для рассмотрения судьей; при принятии заявления выполняется ТБП41 «Провести возврат госпошлины», в рамках которого проверяются основания возврата и оформляется результат рассмотрения. Фактическое перечисление денежных средств осуществляется за пределами ТБП40. |
| **Участники процесса** | Истец/Заявитель; Канцелярия суда; Отдел делопроизводства; Судья; Система |
| **НПА** | Налоговый кодекс Российской Федерации (часть вторая) от 05.08.2000 № 117-ФЗ: ст. 333.40.  Арбитражный процессуальный кодекс Российской Федерации от 24.07.2002 № 95-ФЗ: ст. 104.  Постановление Пленума ВАС РФ от 25.12.2013 № 100 «Об утверждении Инструкции по делопроизводству в арбитражных судах Российской Федерации (первой, апелляционной и кассационной инстанций)»: п. 13.2.  Постановление Пленума Верховного Суда РФ от 23.12.2025 № 39 «О некоторых вопросах уплаты государственной пошлины при рассмотрении дел в судах». |

# 3. Реестр UC

## UC001 — Определение наличия связанного дела

| **Поле** | **Значение** |
| --- | --- |
| **№ шага процесса** | 3–5 |
| **Выполняемая задача** | Автоматически определить наличие связанного дела |
| **Цель** | Определить наличие связанного дела и использовать найденные сведения при дальнейшей обработке заявления без ручного поиска дела. |
| **Роль / Актор** | Сотрудник канцелярии |
| **Ожидаемый результат** | Сформирован результат поиска: связанное дело установлено либо не установлено; при наличии дела получены сведения о нем. |
| **Рекомендуемая функциональность** | Извлечение идентифицирующих сведений из заявления; приоритетный поиск по номеру дела при его наличии; дополнительный поиск по иным идентифицирующим сведениям при отсутствии номера дела либо отсутствии результата; отображение результата поиска и сведений найденного дела. |
| **Критичность** | Необходима |
| **Триггер** | В суд поступило заявление о возврате государственной пошлины. |
| **Предварительные условия** | Заявление доступно Системе; информационная система суда доступна для выполнения поиска. |
| **Основной сценарий** | 1. Система получает сведения поступившего заявления. 2. Система извлекает идентифицирующие сведения. 3. При наличии номера дела Система выполняет поиск по номеру дела. 4. Если номер дела отсутствует либо поиск по нему не дал результата, Система выполняет поиск по иным идентифицирующим сведениям из заявления. 5. Система устанавливает наличие связанного дела и фиксирует сведения о нем. 6. Процесс переходит к шагу 16 для приема и регистрации заявления. |
| **Расширение (альтернативный сценарий)** | 1. Если по результатам поиска связанное дело не установлено, Система фиксирует соответствующий результат. 2. Процесс переходит к шагу 6 для передачи заявления в отдел делопроизводства. |

## UC002 — Проверка сведений при отсутствии связанного дела

| **Поле** | **Значение** |
| --- | --- |
| **№ шага процесса** | 6–12 |
| **Выполняемая задача** | Проверить сведения, содержащиеся в заявлении и документе, подтверждающем уплату государственной пошлины, и оформить справку о непоступлении обращения в суд |
| **Цель** | Автоматизировать проверку формализуемых сведений и предоставить сотруднику проверяемый результат для последующего оформления справки о непоступлении искового заявления, иного заявления или жалобы в суд. |
| **Роль / Актор** | Сотрудник отдела делопроизводства |
| **Ожидаемый результат** | Результаты автоматической проверки подтверждены или скорректированы сотрудником; сформирована и направлена заявителю справка о непоступлении обращения в суд. |
| **Рекомендуемая функциональность** | Извлечение и сопоставление сведений заявления и платежного документа; проверка реквизитов и даты платежа; расчет срока с даты уплаты государственной пошлины и проверка соблюдения установленного срока обращения за возвратом государственной пошлины; фиксация расхождений и отсутствующих сведений; формирование протокола проверки; предоставление сотруднику возможности проверить и скорректировать фактические данные. |
| **Критичность** | Необходима |
| **Триггер** | По результатам автоматического поиска связанное дело не установлено, заявление передано в отдел делопроизводства. |
| **Предварительные условия** | Заявление о возврате государственной пошлины и документ, подтверждающий ее уплату, доступны для автоматической проверки; сформирован результат поиска, согласно которому связанное дело не установлено. |
| **Основной сценарий** | 1. Выполняется передача заявления в отдел делопроизводства. 2. Система извлекает сведения из заявления и документа, подтверждающего уплату государственной пошлины. 3. Система сопоставляет формализуемые сведения, проверяет реквизиты и дату платежа, рассчитывает срок с даты уплаты и фиксирует выявленные расхождения. 4. Система формирует протокол проверки сведений. 5. Сотрудник отдела делопроизводства проверяет результаты автоматической проверки и при необходимости корректирует фактические данные. 6. По подтвержденным сведениям выполняется формирование и подписание справки о непоступлении искового заявления, иного заявления или жалобы в суд. 7. Выполняется направление сформированной справки заявителю. 8. Обработка заявления по данной ветви завершается. |
| **Расширение (альтернативный сценарий)** | 1. Если при проверке результатов автоматической обработки сотрудник выявляет ошибку в извлеченных или рассчитанных данных, фактические сведения корректируются. 2. Для последующего формирования справки используется проверенный и скорректированный сотрудником результат. |

## UC003 — Рассмотрение заявления при наличии связанного дела

| **Поле** | **Значение** |
| --- | --- |
| **№ шага процесса** | 16–21 |
| **Выполняемая задача** | Обеспечить рассмотрение заявления при наличии связанного дела |
| **Цель** | Зарегистрировать поступившее заявление, передать его на рассмотрение судье и при принятии заявления выполнить ТБП41 «Провести возврат госпошлины». |
| **Роль / Актор** | Судья |
| **Ожидаемый результат** | По заявлению получен предусмотренный результат: при принятии заявления выполнен ТБП41 и оформлен результат рассмотрения вопроса о возврате государственной пошлины; при непринятии заявления процесс завершен соответствующим результатом ТБП15. |
| **Рекомендуемая функциональность** | Передача между связанными типовыми процессами необходимых сведений и статусов; сохранение и отображение результатов выполнения ТБП53, ТБП15 и ТБП41 без повторного ввода данных. |
| **Критичность** | Необходима |
| **Триггер** | Система установила наличие связанного дела по поступившему заявлению. |
| **Предварительные условия** | Связанное дело установлено; сведения найденного дела доступны для дальнейшей обработки заявления. |
| **Основной сценарий** | 1. Выполняется ТБП53 «Принять входящий документ», в рамках которого заявление принимается и регистрируется. 2. После регистрации выполняется ТБП15 «Рассмотреть вопрос о возвращении документа». 3. ТБП40 получает результат ТБП15. 4. Если заявление принято, выполняется ТБП41 «Провести возврат госпошлины». 5. В ТБП41 проверяются основания полного или частичного возврата государственной пошлины и оформляется результат рассмотрения. 6. После получения результата ТБП41 рассмотрение заявления в ТБП40 завершается на шаге 20. Фактическое перечисление денежных средств осуществляется за пределами ТБП40. |
| **Расширение (альтернативный сценарий)** | 1. Если по результатам ТБП15 заявление не принято, ТБП41 не выполняется. 2. Процесс завершается на шаге 21 результатом «Заявление о возврате госпошлины не было принято». Процессуальное оформление результата выполняется в рамках ТБП15. |
