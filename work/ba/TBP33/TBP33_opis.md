# [To be] ТБП33. Проверить госпошлину

| **Наименование процесса** | ТБП33 — Проверить госпошлину |
| --- | --- |
| **Суть процесса** | Процесс предназначен для проверки государственной пошлины при поступлении процессуального документа или жалобы. Система проверяет наличие предусмотренных BPMN документов об уплате. При их наличии вызываются ТБП37 «Рассчитать госпошлину» и ТБП26 «Проверить уплату госпошлины», после чего Система сопоставляет сумму из платежных данных с рассчитанной суммой и формирует протокол проверки для ТБП139 «Проверить выводы системы». Если документы об уплате отсутствуют либо результат сравнения суммы ведет по отрицательной ветви, Система последовательно проверяет наличие ходатайства об освобождении, заявления о зачете и ходатайства об отсрочке, рассрочке или уменьшении госпошлины и передает управление в соответствующий типовой процесс. Итог ТБП33 определяется фактически пройденной ветвью и результатом вызванного процесса. |
| **Участники процесса** | Помощник судьи/секретарь СЗ; Система |
| **НПА** | Арбитражный процессуальный кодекс Российской Федерации от 24.07.2002 № 95-ФЗ: ст. 102, п. 2 ч. 1 ст. 126, п. 2 ч. 4 ст. 260, п. 2 ч. 4 ст. 277. Налоговый кодекс Российской Федерации (часть вторая) от 05.08.2000 № 117-ФЗ: гл. 25.3, в том числе ст. 333.18, 333.21, 333.22, 333.35, 333.37, 333.40, 333.41. Постановление Пленума Верховного Суда РФ от 23.12.2025 № 39 «О некоторых вопросах уплаты государственной пошлины при рассмотрении дел в судах», в том числе пп. 1–8. |

При наличии фиксируются найденные документы и их реквизиты; при отсутствии — соответствующий статус. Результат используется исключительно шлюзом 2 для выбора предусмотренного BPMN маршрута.  **Результат шага:** Сформирован однозначный результат проверки наличия документов об уплате. | — |

# **3. Реестр UC**

UC001 — Получение проверенного результата основной платежной ветви

| № шага процесса | 0–9 |
| --- | --- |
| Выполняемая задача | Получение результата автоматизированной проверки документов, расчета и проверки уплаты, сравнения суммы и возврата результата ТБП139. |
| Цель | Получить проверяемый результат основной платежной ветви и определить дальнейший маршрут по критерию сравнения суммы, предусмотренному BPMN. |
| Роль / Актор | Помощник судьи/секретарь СЗ |
| Ожидаемый результат | Получен результат ТБП26, сформирован и проверен протокол сравнения; по результату шлюза 8 процесс либо завершен событием 9, либо передан к проверке альтернативных заявлений/ходатайств. |
| Рекомендуемая функциональность | Автоматический поиск документов; получение результатов ТБП37 и ТБП26; числовое сравнение сумм; формирование протокола; передача протокола в ТБП139; маршрутизация по проверенному результату сравнения. |
| Критичность | Необходима |
| Триггер | Из вызывающего процесса в ТБП33 переданы процессуальный документ/жалоба и материалы, по которым требуется выполнить проверку государственной пошлины. |
| Предварительные условия | Материалы зарегистрированы и доступны Системе; в них может содержаться предусмотренный BPMN документ об уплате; доступны данные для вызова ТБП37 и ТБП26. |
| Основной сценарий | 1. Система проверяет наличие предусмотренных BPMN документов об уплате государственной пошлины.  2. При наличии документа вызывается ТБП37 «Рассчитать госпошлину», и в ТБП33 возвращается рассчитанная сумма.  3. Вызывается ТБП26 «Проверить уплату госпошлины», и в ТБП33 возвращается результат проверки факта уплаты и доступные платежные сведения.  4. Система отдельно сопоставляет числовое значение суммы из платежных данных с рассчитанной суммой.  5. Система формирует протокол, содержащий рассчитанную сумму, результат ТБП26, платежные данные и результат сравнения.  6. Протокол передается в ТБП139 «Проверить выводы системы»; после завершения в ТБП33 возвращается проверенный либо скорректированный результат.  7. Шлюз 8 использует проверенный результат сравнения суммы. При значении «сумма больше либо равна рассчитанной» процесс завершается событием 9 «Госпошлина уплачена». |
| Расширение (альтернативный сценарий) | 1. Если документы об уплате не представлены, шлюз 2 направляет процесс к UC002.  2. Если по проверенному результату сумма меньше рассчитанной, шлюз 8 также направляет процесс к UC002. |

UC002 — Проверка альтернативных заявлений и ходатайств

| № шага процесса | 10–26 |
| --- | --- |
| Выполняемая задача | Последовательная проверка наличия предусмотренных BPMN заявлений/ходатайств, вызов соответствующего типового процесса и фиксация его результата. |
| Цель | Получить конкретный результат по первой применимой альтернативной ветви и завершить ТБП33 с сохранением вида требования и причины результата. |
| Роль / Актор | Помощник судьи/секретарь СЗ |
| Ожидаемый результат | Получен результат ТБП38, ТБП42 или ТБП39 и классифицирован его явно зафиксированный исход либо установлено отсутствие последнего предусмотренного ходатайства; ТБП33 завершен событием 24 или 26. |
| Рекомендуемая функциональность | Автоматический поиск соответствующих заявлений/ходатайств; маршрутизация в ТБП38/ТБП42/ТБП39; прием возвращенного результата; классификация явно зафиксированного исхода без повторной правовой оценки; сохранение конкретного вида требования и причины завершения. |
| Критичность | Необходима |
| Триггер | Основная платежная ветвь не завершилась событием 9: документы об уплате отсутствуют либо проверенный результат сравнения суммы ведет по ветви «Нет». |
| Предварительные условия | Материалы дела и зарегистрированные заявления/ходатайства доступны Системе. |
| Основной сценарий | 1. Система проверяет наличие ходатайства об освобождении от уплаты государственной пошлины.  2. Если ходатайство найдено, вызывается ТБП38; его возвращенный результат через сходящиеся шлюзы передается на шаг 22.  3. Если ходатайство об освобождении отсутствует, Система проверяет наличие заявления о зачете государственной пошлины.  4. Если заявление о зачете найдено, вызывается ТБП42; его возвращенный результат также передается на шаг 22.  5. Если заявление о зачете отсутствует, Система проверяет наличие ходатайства об отсрочке, рассрочке или уменьшении государственной пошлины.  6. Если такое ходатайство найдено, вызывается ТБП39; возвращенный результат передается на шаг 22.  7. Система считывает вид рассмотренного требования и явно зафиксированный исход возвращенного результата и формирует статус «удовлетворено / отказано» без повторной правовой оценки.  8. При статусе «удовлетворено» ТБП33 завершается событием 24 с сохранением конкретного вида требования; при статусе «отказано» — событием 26 с сохранением причины. |
| Расширение (альтернативный сценарий) | 1. Если ходатайство об освобождении отсутствует, проверка продолжается заявлением о зачете; при его отсутствии — ходатайством об отсрочке/рассрочке/уменьшении.  2. Если последнее предусмотренное ходатайство отсутствует, процесс через шлюз 25 завершается событием 26.  3. Если ТБП38 или ТБП42 уже был вызван и вернул отрицательный результат, текущая BPMN после шага 22 не возвращает процесс к проверке следующих альтернативных заявлений/ходатайств. |
