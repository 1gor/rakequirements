# [To be] ТБП26. Проверить уплату госпошлины

| **Наименование процесса** | ТБП26 — Проверить уплату госпошлины |
| --- | --- |
| **Суть процесса** | Процесс предназначен для проверки уплаты государственной пошлины по представленному платежному документу. Система автоматически проверяет форму и порядок оформления платежного документа и корректность банковских реквизитов, формирует протокол проверки, после чего результаты автоматической проверки предоставляются Судье для проверки в ТБП139 «Проверить выводы системы». При недостаточности или противоречивости имеющихся сведений выполняется дополнительная проверка посредством ТБП23 «Направить запрос в ведомство». По совокупности имеющихся сведений формируется автоматический вывод о подтверждении либо неподтверждении уплаты государственной пошлины, который подлежит проверке Судьей. При выявлении формализуемых признаков возможной фальсификации платежного документа Система предоставляет Судье сведения о конкретных несоответствиях и использованных исходных данных. Система самостоятельно не устанавливает факт фальсификации и не принимает процессуальное решение. Вопрос о необходимости вынесения частного определения оценивается Судьей; при подтверждении такой необходимости выполняется ТБП24 «Принять частное определение о нарушении законности». |
| **Участники процесса** | Судья; Система |
| **НПА** | Налоговый кодекс Российской Федерации (часть вторая) от 05.08.2000 № 117-ФЗ: ст. 333.18.  Арбитражный процессуальный кодекс Российской Федерации от 24.07.2002 № 95-ФЗ: ст. 102, п. 2 ч. 1 ст. 126, ст. 188.1.  Федеральный закон от 27.07.2010 № 210-ФЗ «Об организации предоставления государственных и муниципальных услуг»: ст. 21.3. |

# **3. Реестр UC**

## UC001 — Проверка платежного документа и реквизитов

| **№ шага процесса** | 0–6 |
| --- | --- |
| **Выполняемая задача** | Автоматическая проверка платежного документа и банковских реквизитов |
| **Цель** | Проверить форму платежного документа и банковские реквизиты и предоставить результат автоматической проверки Судье. |
| **Роль / Актор** | Судья |
| **Ожидаемый результат** | Судьёй проверены результаты автоматической проверки платежного документа и банковских реквизитов. |
| **Рекомендуемая функциональность** | Автоматическое извлечение сведений платежного документа; проверка формы и порядка оформления; сопоставление банковских реквизитов; формирование протокола с результатами проверок, исходными сведениями и выявленными несоответствиями. |
| **Критичность** | Необходима |
| **Триггер** | Выполнен переход к проверке уплаты государственной пошлины по представленному платежному документу. |
| **Предварительные условия** | Платежный документ доступен Системе для автоматической проверки. |
| **Основной сценарий** | 1. Система проверяет форму и порядок оформления платежного документа. 2. Система проверяет корректность банковских реквизитов. 3. Система формирует протокол проверки платежного документа. 4. Судья проверяет результаты автоматической проверки в ТБП139. 5. Если платежный документ соответствует требованиям и банковские реквизиты корректны, процесс переходит к шагу 7. |
| **Расширение (альтернативный сценарий)** | 1. Если Судья корректирует результаты автоматической проверки, дальнейшее выполнение процесса осуществляется с учетом проверенного результата. 2. Если платежный документ не соответствует требованиям либо банковские реквизиты некорректны, процесс завершается на шаге 6. |

## UC002 — Дополнительная проверка и итог уплаты

| **№ шага процесса** | 7–19 |
| --- | --- |
| **Выполняемая задача** | Дополнительная проверка и формирование результата проверки уплаты государственной пошлины |
| **Цель** | Сформировать результат о подтверждении либо неподтверждении уплаты государственной пошлины с учетом доступных и при необходимости дополнительно полученных сведений. |
| **Роль / Актор** | Судья |
| **Ожидаемый результат** | Судьёй проверен сформированный Системой результат о подтверждении либо неподтверждении уплаты государственной пошлины. |
| **Рекомендуемая функциональность** | Автоматическое определение необходимости дополнительной проверки; использование сведений, полученных посредством ТБП23; сопоставление результатов проверок; формирование сводного результата с указанием использованных сведений и оснований. |
| **Критичность** | Необходима |
| **Триггер** | Платежный документ соответствует требованиям, банковские реквизиты признаны корректными. |
| **Предварительные условия** | Выполнена проверка платежного документа и банковских реквизитов, результаты проверены Судьёй. |
| **Основной сценарий** | 1. Система определяет необходимость дополнительной проверки уплаты. 2. При необходимости выполняется ТБП23 «Направить запрос в ведомство». 3. После получения дополнительных сведений либо при отсутствии необходимости в запросе Система формирует сводный результат проверки уплаты. 4. Если уплата подтверждена, Система предоставляет Судье сведения о положительном результате. 5. Судья проверяет результат в ТБП139. 6. Процесс завершается на шаге 15. |
| **Расширение (альтернативный сценарий)** | 1. Если уплата не подтверждена, выполняется проверка наличия признаков возможной фальсификации платежного документа. 2. Если такие признаки отсутствуют, Система предоставляет Судье сведения о неподтверждении уплаты. 3. Судья проверяет результат в ТБП139. 4. Процесс завершается на шаге 19. 5. Если зафиксированы признаки возможной фальсификации, процесс продолжается по UC003. |

## UC003 — Обработка признаков возможной фальсификации платежного документа

| **№ шага процесса** | 16, 20–27 |
| --- | --- |
| **Выполняемая задача** | Предоставление Судье сведений о признаках возможной фальсификации и рассмотрение вопроса о дальнейших процессуальных действиях |
| **Цель** | Предоставить Судье конкретные сведения о выявленных несоответствиях и обеспечить принятие Судьёй решения по вопросу о необходимости частного определения. |
| **Роль / Актор** | Судья |
| **Ожидаемый результат** | Судья проверил сведения о признаках возможной фальсификации и определил необходимость вынесения частного определения; при необходимости выполнен ТБП24. |
| **Рекомендуемая функциональность** | Отображение конкретных признаков возможной фальсификации и исходных сведений; структурирование сведений, значимых для оценки дальнейших процессуальных действий; формирование объяснимой рекомендации для последующей проверки Судьёй. |
| **Критичность** | Необходима |
| **Триггер** | Уплата государственной пошлины не подтверждена и по результатам автоматических проверок зафиксированы признаки возможной фальсификации платежного документа. |
| **Предварительные условия** | Сформирован автоматический результат проверки уплаты; имеются конкретные несоответствия или сведения, которые могут свидетельствовать о возможной фальсификации платежного документа. |
| **Основной сценарий** | 1. Система предоставляет Судье сведения о выявленных признаках возможной фальсификации с указанием конкретных несоответствий и исходных данных. 2. Система подготавливает структурированные сведения для оценки дальнейших процессуальных действий. 3. Система формирует вспомогательную рекомендацию по вопросу о необходимости вынесения частного определения. 4. Судья проверяет представленные сведения и рекомендацию в ТБП139. 5. Если Судья определяет необходимость вынесения частного определения, выполняется ТБП24 «Принять частное определение о нарушении законности». 6. После завершения предусмотренных действий процесс переходит к шагу 27. |
| **Расширение (альтернативный сценарий)** | 1. Если по результатам проверки Судья определяет, что частное определение не требуется, ТБП24 не выполняется. 2. Процесс через шаг 26 переходит к шагу 27. |
