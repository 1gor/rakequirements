# [To be] ТБП57. Проверить статус ЛУВД

| **Наименование процесса** | ТБП57 — Проверить статус ЛУВД |
| --- | --- |
| **Суть процесса** | Процесс предназначен для проверки статуса лица, участвующего в деле, по двум направлениям: статуса банкротства и специального статуса. Для проверки статуса банкротства Система анализирует сведения по делу, предлагает возможную подсудность банкротного дела, после определения Судьей направления поиска проверяет наличие дела в КАД Арбитр либо ЕПЦП, определяет текущий статус по найденному делу и формирует отчет. Судья проверяет сформированные выводы, после чего в Системе фиксируется подтверждение банкротства либо результат о том, что лицо не является банкротом. Для проверки специального статуса Система устанавливает наличие подтверждающего документа и формирует отчет/ Судья проверяет выводы после чего Система фиксирует подтверждение либо неподтверждение специального статуса. |
| **Участники процесса** | Судья |
| **НПА** | Арбитражный процессуальный кодекс Российской Федерации от 24.07.2002 № 95-ФЗ (ред. от 15.12.2025, с изм. и доп., вступ. в силу с 01.01.2026): гл. 5, в том числе ст. 40–41; гл. 28, в том числе ст. 223. Федеральный закон от 26.10.2002 № 127-ФЗ «О несостоятельности (банкротстве)» (ред. от 04.08.2026): ст. 2, 27, 28, 34. |

# 3. Реестр UC

**UC001 — Проверка статуса банкрота**

| **№ шага процесса** | 3-19 |
| --- | --- |
| **Выполняемая задача** | Проверить статус банкрота по данным о найденном деле и сформировать итоговый вывод в Системе. |
| **Цель** | Зафиксировать текущий статус банкротства и результат проверки для дальнейшего принятия решения. |
| **Роль / Актор** | Судья |
| **Ожидаемый результат** | В Системе отображен и сохранен результат проверки статуса банкротства лица. |
| **Рекомендуемая функциональность** | Сервисные запросы на актуализацию статуса и формирование отчета по данным дела. |
| **Критичность** | Необходимая |
| **Триггер** | Судья инициирует формирование отчета по результатам проверки статуса |
| **Предварительные условия** | В Системе сохранены результаты поиска и доступна информация о найденном деле о банкротстве для определения текущего статуса. |
| **Основной сценарий** | 1. Судья инициирует выбор варианта источника для поиска банкротного дела. 2. Система сохраняет предложение о том, где выполнять поиск банкротного дела (ПК САД или КАД Арбитр). 3. Судья инициирует поиск банкротного дела в выбранной информационной системе по реквизитам. 4. Система сохраняет результат поиска в КАД Арбитр для последующей проверки. 5. Судья использует сохраненные сведения и инициирует проверку наличия дела о банкротстве в КАД Арбитр. 6. Система отражает итог проверки наличия дела о банкротстве в КАД Арбитр (дело найдено/не найдено). 7. Судья запускает сервисный запрос на поиск дела о банкротстве в Системе по реквизитам лица и/или делу. 8. Система устанавливает значение признака «дело о банкротстве найдено/не найдено». 9. Судья инициирует поиск дела о банкротстве и передает в Систему данные из контекста дела. 10. Система сохраняет результаты поиска дела о банкротстве 11. Система формирует набор данных для проверки вопроса «Дело о банкротстве найдено?». 12. Судья инициирует сервисный запрос на актуализацию сведений о текущем статусе банкротства по данным дела. 13. Система фиксирует текущий статус банкротства по найденному делу. 14. Судья инициирует формирование отчета по итогам проверки статуса банкротства. 15. Система создает отчет и подготавливает материал для дальнейшего формирования итогового решения. 16. Судья подтверждает, что лицо является банкротом. 17. Система подтверждает статус банкротства лица, устанавливая значение «Лицо является банкротом: подтверждено». |
| **Расширение (альтернативный сценарий)** | 1. Судья отражает в Системе, что статус банкротства лица не подтвержден. 2. Система устанавливает значение «Лицо является банкротом: не подтверждено». 3. Система обновляет карточку проверки специального статуса и направляет исполнение по дальнейшей проверке подтверждающих документов. |

**UC002 — Проверка специального статуса**

| **№ шага процесса** | 20-27 |
| --- | --- |
| **Выполняемая задача** | Выполнить проверку специального статуса на основании наличия подтверждающего документа и его реквизитов. |
| **Цель** | Определить подтверждение или неподтверждение специального статуса ЛУВД. |
| **Роль / Актор** | Судья |
| **Ожидаемый результат** | Система установила статус «Специальный статус подтвержден» или «Специальный статус не подтвержден» по результатам проверки. |
| **Рекомендуемая функциональность** | Проверка наличия подтверждающих документов; фиксация результата подтверждения специального статуса; обновление статуса проверки по карточке дела. |
| **Критичность** | Необходимая |
| **Триггер** | Судья инициирует проверку специального статуса. |
| **Предварительные условия** | В Системе сформированы результаты предшествующего этапа определения направления проверки для карточки дела. |
| **Основной сценарий** | 1. Судья проверяет наличие подтверждающего документа. 2. Судья формирует отчет. 3. Судья вводит реквизиты подтверждающего документа. 4. Судья выполняет сопоставление указанных сведений с данными дела. 5. Судья проверяет допустимость документа для подтверждения специального статуса ЛУВД. 6. Система устанавливает статус «Специальный статус подтвержден» 7. Система формирует запись результата подтверждения по делу. |
| **Расширение (альтернативный сценарий)** | 1. Судья принимает решение о неподтверждении специального статуса, и Система устанавливает статус «Специальный статус не подтвержден» и обновляет запись статуса проверки по делу. |
