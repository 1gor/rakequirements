# [To be] ТБП127. Рассмотреть корпоративный спор

| **Наименование процесса** | ТБП127 — Рассмотреть корпоративный спор |
| --- | --- |
| **Суть процесса** | Процесс в TO BE описывает формирование судьёй вывода по существу требований, заявленных в рамках корпоративного спора, с использованием Системы для выполнения отдельных автоматизированных проверок. Основная ветвь начинается после перехода судьи к вынесению решения: судья устанавливает причинно-следственную связь, значительность нарушения, наличие ущерба или ущемления прав; Система определяет наличие спора об оспаривании сделки. При наличии такого спора судья последовательно оценивает мнимость сделки, наличие предпочтения кредитору, цель совершения сделки и её порок, после чего формирует вывод по первоначальному иску. Система проверяет наличие принятого встречного иска; при его удовлетворении судья определяет необходимость зачета, а Система выполняет расчет. Отдельной ветвью предусмотрена проверка соблюдения тайны совещательной комнаты: при подтверждении нарушения Система блокирует дальнейшее вынесение судебного акта. |
| **Участники процесса** | Судья, Система |

Федеральный закон от 26.12.1995 № 208-ФЗ «Об акционерных обществах». Федеральный закон от 08.02.1998 № 14-ФЗ «Об обществах с ограниченной ответственностью». Постановление Пленума Верховного Суда Российской Федерации от 23.06.2015 № 25 «О применении судами некоторых положений раздела I части первой Гражданского кодекса Российской Федерации». Постановление Пленума Верховного Суда Российской Федерации от 23.12.2021 № 46 «О применении Арбитражного процессуального кодекса Российской Федерации при рассмотрении дел в суде первой инстанции». Постановление Пленума Высшего Арбитражного Суда Российской Федерации от 30.07.2013 № 62 «О некоторых вопросах возмещения убытков лицами, входящими в состав органов юридического лица» |

# 3. Реестр UC

**UC001 — Проверка тайны совещательной**

| **№ шага процесса** | 1–7 |
| --- | --- |
| **Выполняемая задача** | Проверить соблюдение тайны совещательной комнаты и зафиксировать возможность продолжения принятия решения либо необходимость прекращения процесса. |
| **Цель** | Обеспечить фиксацию результата проверки тайны совещательной комнаты перед дальнейшим вынесением судебного акта. |
| **Роль / Актор** | Судья |
| **Ожидаемый результат** | В Системе зафиксирован результат проверки тайны совещательной комнаты; при подтверждении нарушения доступ к вынесению судебного акта закрыт. |
| **Рекомендуемая функциональность** | Предоставление формы проверки тайны совещательной комнаты, фиксация ответа судьи и блокирование доступа к вынесению судебного акта при подтверждённом нарушении. |
| **Критичность** | Необходимая |
| **Триггер** | Судья запрашивает форму проверки соблюдения тайны совещательной комнаты. |
| **Предварительные условия** | Судья осуществляет принятие решения по корпоративному спору; Система доступна для фиксации результата проверки. |
| **Основной сценарий** | 1. Судья запрашивает в Системе форму проверки соблюдения тайны совещательной комнаты.  2. Система отображает форму по вопросу соблюдения тайны совещательной комнаты.  3. Судья указывает в форме отсутствие нарушения тайны совещательной комнаты.  4. Судья подтверждает результат проверки.  5. Система отображает сохранение результата проверки соблюдения тайны совещательной комнаты. |
| **Расширение (альтернативный сценарий)** | 3а. Судья указывает в форме наличие нарушения тайны совещательной комнаты.  3а1. Система отображает, что доступ к вынесению судебного акта закрыт. |

**UC002 — Решение по первоначальному иску**

| **№ шага процесса** | 8–18 |
| --- | --- |
| **Выполняемая задача** | Сформировать вывод по первоначальному иску на основании оценки нарушений, последствий и, при наличии, обстоятельств спорной сделки. |
| **Цель** | Подготовить обоснованный вывод о наличии либо отсутствии оснований для удовлетворения первоначального иска в корпоративном споре. |
| **Роль / Актор** | Судья |
| **Ожидаемый результат** | Судьёй сформирован вывод по вопросу удовлетворения первоначального иска. |
| **Рекомендуемая функциональность** | Рабочее место судьи для фиксации выводов по обстоятельствам корпоративного спора и автоматизированная проверка наличия спора об оспаривании сделки. |
| **Критичность** | Необходимая |
| **Триггер** | Судья перешёл к формированию решения по существу первоначальных требований корпоративного спора. |
| **Предварительные условия** | В Системе доступно дело корпоративного спора и материалы, необходимые для оценки заявленных требований. |
| **Основной сценарий** | 1. Судья фиксирует в Системе вывод о наличии либо отсутствии причинно-следственной связи между нарушением и последствиями.  2. Судья фиксирует в Системе вывод о значительности нарушения.  3. Судья фиксирует в Системе вывод о наличии либо отсутствии ущерба или ущемления прав и законных интересов.  4. Система отображает признак наличия спора об оспаривании сделки.  5. Судья фиксирует в Системе вывод о наличии либо отсутствии признаков мнимости сделки.  6. Судья фиксирует в Системе вывод о наличии либо отсутствии предпочтения кредитору.  7. Судья фиксирует в Системе вывод о цели совершения сделки.  8. Судья фиксирует в Системе вывод о наличии либо отсутствии порока сделки.  9. Судья фиксирует в Системе вывод о том, подлежит ли первоначальный иск удовлетворению. |
| **Расширение (альтернативный сценарий)** | 4а. Система отображает признак отсутствия спора об оспаривании сделки.  4а1. Судья фиксирует вывод по первоначальному иску без выводов по спорной сделке. |

**UC003 — Рассмотрение встречного иска и зачёт требований**

| **№ шага процесса** | 19–29 |
| --- | --- |
| **Выполняемая задача** | Разрешить встречный иск и определить необходимость зачёта сумм. |
| **Цель** | Учесть встречные требования и результат зачёта при завершении рассмотрения корпоративного спора. |
| **Роль / Актор** | Судья |
| **Ожидаемый результат** | Определён результат рассмотрения встречного иска; при необходимости Системой рассчитан и сохранён результат зачёта сумм. |
| **Рекомендуемая функциональность** | Проверка статуса встречного иска, фиксация решения судьи по встречным требованиям и автоматизированный расчёт зачёта сумм. |
| **Критичность** | Необходимая |
| **Триггер** | Судья сохранил вывод по первоначальному иску. |
| **Предварительные условия** | В Системе зафиксирован результат рассмотрения первоначального иска; доступны сведения о наличии и статусе встречного иска. |
| **Основной сценарий** | 1. Судья открывает в Системе сведения о встречных требованиях по делу.  2. Система отображает признак наличия встречного иска, принятого к производству.  3. Судья фиксирует в Системе вывод об удовлетворении встречного иска.  4. Судья выбирает в Системе опцию о необходимости зачёта сумм.  5. Система отображает рассчитанный результат зачёта сумм. |
| **Расширение (альтернативный сценарий)** | 2а. Система отображает отсутствие принятого к производству встречного иска.  3а. Судья фиксирует вывод об отказе в удовлетворении встречного иска.  4а. Судья выбирает опцию об отсутствии необходимости зачёта сумм. |
