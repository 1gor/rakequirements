| **Наименование процесса** | ТБП80:Принять СА |
| **Суть процесса** | Процесс начинается с момента, когда судья приходит к выводу о необходимости вынесения судебного акта - как итогового по результатам рассмотрения дела, так и отдельного судебного акта по процессуальному вопросу, возникшему в ходе судопроизводства. В рамках процесса судья определяет, выносится ли судебный акт в ходе судебного заседания, по его итогам либо без проведения судебного заседания (в упрощённом или документарном порядке), а также устанавливает, принимается ли судебный акт единолично или коллегиально. Судья определяет, изготовлен ли судебный акт в полном объёме с мотивировочной частью либо только в резолютивной части. При наличии оснований изготавливается мотивированная часть решения. Параллельно осуществляется публикация судебного акта в установленной законом информационной системе, за исключением случаев рассмотрения дела в закрытом судебном заседании или наличия охраняемой законом тайны. После этого при необходимости изготавливаются и заверяются копии судебного акта для направления лицам, участвующим в деле, либо направляется оригинал судебного акта в суд вышестоящей инстанции. Процесс завершается выполнением всех предусмотренных законом действий по изготовлению и направлению экземпляров судебного акта/ оригинала судебного акта. |
| **Участники процесса** | Судья |
| **НПА** | Арбитражный процессуальный кодекс Российской Федерации от 24.07.2002 N 95-ФЗ (ред. от 01.04.2025)  Постановление Пленума ВАС РФ от 25.12.2013 N 100 (ред. от 11.07.2014) "Об утверждении Инструкции по делопроизводству в арбитражных судах Российской Федерации (первой, апелляционной и кассационной инстанций)"  Федеральный закон от 26.10.2002 N 127-ФЗ (ред. от 31.07.2025) "О несостоятельности (банкротстве)" (с изм. и доп., вступ. в силу с 01.09.2025) |

2.3.Реестр UC (в части выполняемых пользователем задач и рекомендованной функциональности Системы)UC-001 Формирование проекта СА

|  |  |
| --- | --- |
| Поле | Значение |
| Выполняемая задача | Сформировать проект судебного акта (СА) и подготовить его к подписанию. |
| № шага процесса | 0-8, 27-32 |
| Цель | сформировать проект СА для последующего подписания УКЭП |
| Роль / Актор | Судья |
| Ожидаемый результат | В системе сформирован проект СА и он доступен судье для проверки и дальнейшего подписания. |
| Рекомендованная функциональность | Создание проекта СА на основании данных дела; отображение проекта судье; уведомление о готовности проекта; возможность внесения дополнительной информации и повторного формирования проекта; сохранение версии проекта. |
| Критичность | Необходимая |
| Триггер | Судья нажал в карточке дела действие "Сформировать проект СА". |
| Предварительные условия | Судья авторизован в системе. Открыта карточка дела. Данные дела заполнены в объеме, достаточном для формирования проекта СА. |
| Основной сценарий | 1. Судья выбирает в карточке дела действие "Сформировать проект СА". 2. Система формирует проект СА. 3. Система сохраняет проект СА в статусе "Проект". 4. Система уведомляет судью о готовности проекта СА. 5. Судья открывает проект СА. 6. Система отображает судье сформированный проект СА. 7. Судья выбирает действие "Проверить выводы системы". 8. Система отображает судье результаты проверки выводов системы. 9. Судья нажимает кнопку "Подтвердить корректность" для проекта СА. 10. Система фиксирует результат проверки проекта СА. 11. Система переводит проект в статус "Готов к подписанию". |
| Альтернативные сценарии / расширения | 5а. Судья открывает проект СА из уведомления о готовности проекта. 5б. Судья открывает проект СА из карточки дела. 9а. Судья выбирает действие "Внести дополнительную информацию". 9а1. Система отображает форму ввода дополнительной информации. 9а2. Судья вводит дополнительную информацию и нажимает кнопку "Сохранить". 9а3. Система сохраняет введенные данные. 9а4. Система обновляет проект СА. 9а5. Система отображает судье обновленный проект СА. 9а6. Судья нажимает кнопку "Подтвердить корректность" для обновленного проекта СА. 9а7. Система фиксирует результат проверки проекта СА. 9а8. Система переводит проект в статус "Готов к подписанию". |

|  |  |
| --- | --- |
| Поле | Значение |
| Выполняемая задача | Подписать сформированный проект СА усиленной квалифицированной электронной подписью (УКЭП). |
| № шага процесса | 33-34 |
| Цель | подписать СА УКЭП и зафиксировать подписанный СА в деле |

| Рекомендованная функциональность | Отображение кнопки подписания; интеграция с механизмом УКЭП; проверка полномочий; выполнение подписания с формированием открепленной подписи; фиксация факта подписи и реквизитов подписи; сохранение подписанного СА и подписи в деле. |

| Основной сценарий | 1. Судья открывает проект СА и выбирает действие "Подписать УКЭП". 2. Система отображает запрос подтверждения подписания. 3. Судья подтверждает подписание УКЭП. 4.
