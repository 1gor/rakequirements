# [To be] ТБП43. Контроль отсрочки/рассрочки ГП

| **Наименование процесса** | ТБП43 — Контроль отсрочки/рассрочки ГП |
| --- | --- |
| **Суть процесса** | Процесс предназначен для контроля установленного срока либо контрольной даты графика уплаты государственной пошлины после предоставления отсрочки или рассрочки. Система контролирует наступление контрольной даты и наличие предусмотренного BPMN платежного документа. При наличии документа выполняется ТБП26 «Проверить уплату госпошлины». В зависимости от подтвержденной даты уплаты и статуса дела Система формирует протокол соответствующей ветви, который передается в ТБП139 «Проверить выводы системы». Далее текущая BPMN предусматривает завершение контроля при подтвержденной уплате, переход к ТБП15 по ветви поздней уплаты после прекращения производства либо вызов ТБП109 по отрицательной ветви. |
| **Участники процесса** | Судья; Система |
| **НПА** | Арбитражный процессуальный кодекс Российской Федерации от 24.07.2002 № 95-ФЗ: ст. 102, 150–151.  Налоговый кодекс Российской Федерации (часть первая) от 31.07.1998 № 146-ФЗ: ст. 64.  Налоговый кодекс Российской Федерации (часть вторая) от 05.08.2000 № 117-ФЗ: ст. 333.18, 333.41.  Постановление Пленума Верховного Суда РФ от 23.12.2025 № 39 «О некоторых вопросах уплаты государственной пошлины при рассмотрении дел в судах»: пп. 1–2, 6. |

# **3. Реестр UC**

UC001 — Контроль срока и подтверждение уплаты

| № шага процесса | 0–12 |
| --- | --- |
| Выполняемая задача | Контроль установленной контрольной даты, получение результата проверки уплаты и завершение ветви, которую BPMN ведет к результату «госпошлина уплачена». |
| Цель | Получить проверяемый результат контроля даты и уплаты и завершить соответствующую ветвь после возврата результата ТБП139. |
| Роль / Актор | Судья |
| Ожидаемый результат | Сформирован протокол с исходными данными; после ТБП139 получен возвращаемый результат; ветвь завершена конечным событием 12. |
| Рекомендуемая функциональность | Контроль текущей контрольной даты; проверка наличия платежного документа; вызов ТБП26; сопоставление даты платежа с контрольной датой; проверка статуса дела при поздней уплате; формирование протокола и передача его в ТБП139. |
| Критичность | Необходима |
| Триггер | В ТБП43 переданы сведения о предоставленной отсрочке/рассрочке, текущая контрольная дата либо дата графика и данные дела. |
| Предварительные условия | Системе доступны данные дела и текущая контрольная дата; поступающие документы доступны для предусмотренной BPMN проверки. |
| Основной сценарий | 1. Система контролирует текущую контрольную дату и проверяет наличие предусмотренного BPMN платежного документа.  2. Если документ поступил, выполняется ТБП26 «Проверить уплату госпошлины», после чего в ТБП43 возвращается результат проверки факта уплаты; для контроля срока используется дата платежа из доступных исходных сведений об оплате.  3. Если уплата подтверждена не позднее контрольной даты, процесс переходит к шагу 10 через шлюз 9.  4. Если уплата подтверждена после контрольной даты, Система проверяет статус производства по делу.  5. Если производство не прекращено, поздняя уплата также направляется через шлюз 9 к формированию протокола.  6. Система формирует протокол с контрольной датой, данными платежа, результатом ТБП26 и сведениями о пройденной ветви.  7. Протокол передается в ТБП139 «Проверить выводы системы».  8. После возврата результата ТБП139 текущая BPMN завершает ветвь конечным событием 12 «Госпошлина уплачена». |
| Расширение (альтернативный сценарий) | 1. Если платежный документ не поступил, используется сценарий UC003.  2. Если ТБП26 не подтвердил уплату, используется сценарий UC003.  3. Если уплата подтверждена после контрольной даты и производство по делу прекращено, используется сценарий UC002. |

UC002 — Поздняя уплата по прекращенному делу

| № шага процесса | 7–8, 13–16 |
| --- | --- |
| Выполняемая задача | Обработка ветви подтвержденной поздней уплаты, когда Система установила статус «производство прекращено». |
| Цель | Сформировать и проверить протокол этой ветви, выполнить предусмотренный BPMN вызов ТБП15 и завершить процесс конечным событием 16. |
| Роль / Актор | Судья |
| Ожидаемый результат | Сформирован протокол поздней уплаты; после ТБП139 получен возвращаемый результат; выполнен ТБП15; ветвь завершена конечным событием 16. |
| Рекомендуемая функциональность | Получение статуса дела; формирование протокола поздней уплаты; передача протокола в ТБП139; вызов ТБП15; фиксация результата текущей BPMN. |
| Критичность | Необходима |
| Триггер | ТБП26 подтвердил факт уплаты; сопоставление даты платежа с контрольной датой установило уплату после срока, а шаг 7 сформировал статус «производство прекращено». |
| Предварительные условия | Доступны результат ТБП26, контрольная дата, статус дела и платежный документ — если он существует как самостоятельный объект. |
| Основной сценарий | 1. Система фиксирует статус дела «производство прекращено».  2. Система формирует протокол с контрольной датой, подтвержденной датой платежа, результатом ТБП26 и статусом производства.  3. Протокол передается в ТБП139 «Проверить выводы системы».  4. После возврата результата ТБП139 текущая BPMN вызывает ТБП15 «Рассмотреть вопрос о возвращении документа».  5. После завершения ТБП15 ТБП43 завершается конечным событием 16. |
| Расширение (альтернативный сценарий) | 1. Если на шаге 8 установлено, что производство не прекращено, используется сценарий UC001.  2. Иной маршрут после возврата результата ТБП139 текущей BPMN не предусмотрен. |

После завершения вызванного процесса ТБП43 завершается конечным событием 20. |
