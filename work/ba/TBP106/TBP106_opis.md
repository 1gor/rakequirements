# Описание ТБП106: "Передать документ" TO BE

|  |  |
| --- | --- |
| **Наименование процесса** | ТБП106.Передать документ |
| **Суть процесса** | Процеcc описывает процедуру передачи документа внутри суда. Процесс инициирует либо запрос сотрудника суда на предоставление документа, либо инициатива сотрудника суда предоставить документ внутри суда в тех или иных целях. В рамках процесса формируется реестр передачи с внесением всех необходимых в рамках процедуры данных, за чем следует непосредственно сама передача и принятие документа по этому реестру. Процесс завершается после подтверждения сотрудника суда успешного принятия документа. |
| **Участники процесса** | Лицо, передающее документ, Лицо/отдел, принимающее документ |
| **НПА** | Постановление Пленума ВАС РФ от 25.12.2013 N 100 (ред. от 11.07.2014) Об утверждении Инструкции по делопроизводству в арбитражных судах Российской Федерации (первой, апелляционной и кассационной инстанций) |

## **1. Реестр US**

|  |  |  |  |
| --- | --- | --- | --- |
| **№** | **Я КАК** | **ХОЧУ** | **ЧТОБЫ** |
| 01 | Лицо, передающее документ | выбрать документ, указать получателя и причину передачи в системе | инициировать процедуру внутренней передачи непроцессуального документа |
| 02 | Лицо, передающее документ | получить уведомление и ознакомиться с причиной отказа в приеме документа | исправить ошибки или основания передачи и повторить отправку |
| 03 | Лицо/отдел, принимающее документ | получить документ, ссылку на запись в реестре и проверить основания передачи | принять решение о возможности приема документа |
| 04 | Лицо/отдел, принимающее документ | принять решение о приеме или отказе в приеме документа | завершить процедуру передачи и закрепить документ за ответственным лицом |

## 2.2 Описание схемы бизнес-процессов

|  |  |  |  |
| --- | --- | --- | --- |
| **№** | **Наименование элемента** | **Описание** | **Выявленные нормативные ограничения** |
| 0 | Поступил запрос на передачу документа внутри суда/по собственной инициативе сотрудник суда переходит к передаче документа | Тип: Простое начальное событие Назначение: Запуск процесса. |  |
| 1 | Выбрать документ для передачи | Тип: Пользовательская задача  Назначение: Выбор документа вручную пользователем позволяет системе идентифицировать конкретный документ для последующей обработки и маршрутизации.  Роль: Лицо, передающее документ  Входящие данные: Отсутствуют  Исходящие данные: Отсутствуют  Описание: Пользователь выбирает карточку документа, зарегистрированного в системе и подлежащего передаче. |  |
| 2 | Указать, кому и в каких целях передается документ | Тип: Пользовательская задача  Назначение: Выбор адресата пользователем позволит системе точно маршрутизировать документ и определить конкретную точку доставки, учитывая пожелание пользователя; цель необходимо зафиксировать для дальнейшего отображения в реестре и сверки данных адресатом.  Роль: Лицо, передающее документ  Входящие данные: Отсутствуют  Исходящие данные: Отсутствуют  Описание: Пользователь заполняет электронную форму передачи документа в части адресата (путем выбора сотрудника из списка) и в части целей направления (ответ на поступивший от сотрудника запрос на представление документа, собственная инициатива, иная цель). |  |
| 3 | Сформировать запись в реестре передачи | Тип: Сервисная задача  Назначение: Отображение данных о передаче документа (реквизиты документа, адресат, цель передачи, дата и время передачи, статус передачи) в едином реестре передачи для сохранения историчности действий пользователей в контексте передачи документации внутри суда.  Роль: Система  Входящие данные: Отсутствуют  Исходящие данные: Запись в реестре передачи  Описание: Система обрабатывает данные, внесенные пользователем, и формирует отдельную запись в реестре передачи с указанием всех данных, в т.ч. дату и время, статус передачи. | Постановление Пленума ВАС РФ от 25.12.2013 N 100 (ред. от 11.07.2014) Об утверждении Инструкции по делопроизводству в арбитражных судах Российской Федерации (первой, апелляционной и кассационной инстанций) |
| 4 | Направить документ и ссылку на запись в реестре | Тип: Сервисная задача  Назначение: Маршрутизация документа.  Роль: Система  Входящие данные: Запись в реестре передачи, направляемый документ  Исходящие данные: Отсутствуют  Описание: Система направляет тело документа и ссылку на запись в реестре лицу, указанному в графе адресата, для ознакомления. | Постановление Пленума ВАС РФ от 25.12.2013 N 100 (ред. от 11.07.2014) Об утверждении Инструкции по делопроизводству в арбитражных судах Российской Федерации (первой, апелляционной и кассационной инстанций) |
| 5 | Оценить корректность полученных данных | Тип: Пользовательская задача  Назначение: Оценка данных со стороны пользователя-адресата позволяет обеспечить достижение цели процесса – успешное получение сотрудником необходимого (запрашиваемого) документа; оценка позволит избежать возможных ошибок при передаче, как технического, так и человеческого характера, а также зафиксировать актуальные данные в реестре во избежание неточных исторических данных.  Роль: Лицо/отдел, принимающее документ  Входящие данные: Запись в реестре передачи, направляемый документ  Исходящие данные: Отсутствуют  Описание: Получатель документа проверяет корректность следующих данных:   1. Данные в графе «Адресат» 2. Данные в графе «Цель передачи» 3. Реквизиты документа (нужный ли документ поступил).   На основе анализа лицо делает вывод о том, можно ли принять поступивший документ или нет. Если все корректно и документ можно принять, пользователь переходит к подтверждению принятия документа (шаг 10), если выявлены несоответствия – пользователь переходит к отказу в принятии (шаг 7). |  |
| 6 | Данные корректны? | Тип: Развилка «ИЛИ/ИЛИ»  Назначение: Маршрутизация процесса. |  |
| 7 | Отказать в приеме документа | Тип: Пользовательская задача  Назначение: Отказ в приеме документа на основании выполненной проверки позволит избежать ситуаций, когда документ был передан не тому лицу, либо был передан не тот документ и иных ситуаций, влекущих за собой нежелательные для пользователей последствия. Отказ в приеме с внесением причины отказа также обеспечивает своевременное реагирование системы и сотрудника, ответственного за отправку.  Роль: Лицо/отдел, принимающее документ  Входящие данные: Запись в реестре передачи, направляемый документ  Исходящие данные: Отсутствуют  Описание: Пользователь отказывает в приеме документа путем нажатия соответствующей кнопки. В соответствующей графе пользователь также указывает причину отказа, например, поступил не тот документ, который был запрошен, либо цель направления не соответствует фактической. |  |
| 8 | Уведомить лицо, направлявшее документ, об отказе в приеме | Тип: Сервисная задача  Назначение: Передача информации об отказе в приеме для дальнейшего реагирования со стороны пользователя.  Роль: Система  Входящие данные: Данные об отказе  Исходящие данные: Уведомление об отказе в приеме документа  Описание: Система направляет уведомление об отказе в приеме с записью о причине отказа лицу, инициировавшему передачу. | Постановление Пленума ВАС РФ от 25.12.2013 N 100 (ред. от 11.07.2014) Об утверждении Инструкции по делопроизводству в арбитражных судах Российской Федерации (первой, апелляционной и кассационной инстанций) |
| 9 | Документ не передан. При необходимости передачи процесс начнется с первого шага. | Тип: Простое завершающее событие  Назначение: Завершение процесса передачи документа. |  |
| 10 | Одобрить прием документа | Тип: Пользовательская задача  Назначение: Подтверждение корректности данных для последующего отображения в реестре.  Роль: Лицо/отдел, принимающее документ  Входящие данные: Запись в реестре передачи, направляемый документ  Исходящие данные: Отсутствуют  Описание: Пользователь подтверждает принятие документа на своей стороне путем нажатия соответствующей кнопки в Системе. |  |
| 11 | Подписать реестр УКЭП | Тип: Пользовательская задача  Назначение: Отображение в реестре доказательства получения сотрудником документа в формате подписи.  Роль: Лицо/отдел, принимающее документ  Входящие данные: Запись в реестре передачи  Исходящие данные: Отсутствуют  Описание: Лицо, принимающее документ, подписывает электронный реестр УКЭП. |  |
| 12 | Закрепить ответственного за документом | Тип: Сервисная задача  Назначение: Указание ответственного за документ лица позволяет отследить, на чьей стороне документ находится, какой сотрудник в данный момент работает над документом и имеет к нему полный доступ.  Роль: Система  Входящие данные: Отсутствуют  Исходящие данные: Данные об ответственном лице  Описание: Система фиксирует ФИО ответственного сотрудника (сотрудника, принявшего документ) в соответствующем поле (графе, строке) в карточке переданного документа. |  |
| 13 | Документ передан | Тип: Простое завершающее событие  Назначение: Завершение процесса передачи документа. |  |

2.3. Реестр UC

UC-001: Передача документа по электронному реестру передачи

|  |  |
| --- | --- |
| № шага процесса | 1-13 |
| Выполняемая задача | Направление документа сотруднику суда с формированием новой записи в реестре передачи |
| Цель | Получение адресатом корректного документа с актуализацией данных в реестре передачи |
| Роль / Актор | Лицо, передающее документ |
| Ожидаемый результат | Документ получен адресатом, сформирована новая запись в реестре передачи со следующими данными:   1. Дата и время передачи 2. ФИО лица, передающего документ 3. Реквизиты документа 4. Цель передачи 5. ФИО лица-адресата 6. Статус передачи |
| Рекомендованная функциональность | Автоматическое формирование записи в электронном реестре передачи, создание гиперссылки на карточку документа, привязка записи реестра к карточке документа, направление уведомления сотруднику, доступ для просмотра переданных документов, функционал направления артефактов зарегистрированным сотрудникам |
| Критичность | Высокая |
| Триггер | Лицо, передающее документ, нажал кнопку «Направить документ сотруднику суда» в выбранной карточке документа. |
| Предварительные условия | 1. Карточка дела / документа существует в системе. 2. Сотрудники авторизованы в системе и имеют доступ к функционалу просмотра карточки(ек) документов. 3. В системе существуют правила для автоматического направления документов. |
| Основной сценарий | 1.Сотрудник суда запускает функцию отправки в карточке документа.  2.Система открывает экранную форму направления документа.  3. Система предлагает заполнить ФИО адресата и цель передачи.  4. Сотрудник находит и выбирает ФИО адресата из списка сотрудников, зарегистрированных в системе.  5. Сотрудник заполняет цель передачи.  5. Система формирует новую запись в реестре передачи.  6. Система заполняет запись данными, указанными сотрудником.  7. Система записывает дату и время.  8. Система направляет ссылку на карточку документа и запись в реестре адресату, указанному в графе «ФИО адресата».  9. Система устанавливает в записи реестра статус «Направлено».  10. Лицо/отдел, принимающее документ, открывает карточку документа по ссылке.  11. Лицо/отдел, принимающее документ, подтверждает получение в системе.  12. Лицо/отдел, принимающее документ, подписывает реестр УКЭП.  12. Система отображает новый статус «Получено» в записи реестра.  13. Система записывает ФИО адресата как ответственного в карточке отправленного документа. |
| Расширение (альтернативный сценарий) | 10а. Лицо/отдел, принимающее документ, выявляет ошибку передачи.  10а.1. Лицо/отдел, принимающее документ, отказывает в приеме документа.  10а.2. Система отображает форму указания причины отказа в принятии.  10а.3. Лицо/отдел, принимающее документ, указывает причину отказа.  10а.4. Лицо/отдел, принимающее документ, запускает отправку внесенных данных.  10а.5. Система отображает в электронном реестре статус «Выявлено несоответствие»  10а.6. Система отображает сообщение о том, что сведения о несоответствии сохранены  10а.7. Система направляет данные об отказе лицу, инициировавшему направление документа. |
