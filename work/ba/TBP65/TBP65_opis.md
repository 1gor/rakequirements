| **Наименование процесса** | ТБП65: Передать дело по подсудности |
| **Суть процесса** | Процесс начинается с момента, когда судом выявляется нарушение территориальной, родовой либо иной подсудности, а также при выявлении иных предусмотренных законом оснований для передачи по подсудности. В рамках процесса судья определяет надлежащий арбитражный суд или надлежащий СОЮ, уполномоченный на рассмотрение дела, и принимает судебный акт о передаче дела по подсудности. После вынесения определения обеспечивается его подписание, приобщение к материалам дела и направление копий лицам, участвующим в деле. По истечении срока 10 дней; срок на обжалование определения в апелляционном суде, осуществляется подготовка материалов дела к передаче: формирование и проверка состава дела, оформление в соответствии с требованиями делопроизводства, регистрация передачи в информационной системе суда и фактическое направление дела в соответствующий арбитражный суд или СОЮ. Процесс завершается передачей дела по подсудности в другой суд и фиксацией данного факта в учетных и информационных системах. |

| Роль (в соответствии со схемой) | Судья |
| Ожидаемый результат | В карточке дела зафиксирован выбранный суд для передачи по подсудности. |
| Рекомендованная функциональность | Определение вида спора по данным дела; подбор суда для передачи (СОЮ/АС); отображение доступных вариантов; сохранение выбранного суда в данных дела; журналирование действий. |
| Критичность | необходимая |
| Триггер | Судья инициирует действие «Передать дело по подсудности» в карточке дела. |
| Предварительные условия | Открыта карточка дела; у судьи есть права на запуск передачи по подсудности; в деле заполнены сведения, позволяющие определить вид спора. |
| Основной сценарий | 1. Судья инициирует действие «Передать дело по подсудности». 2. Система определяет вид спора на основании данных дела. 3. Система отображает пользователю результат определения вида спора. 4. Система формирует список доступных судов для передачи по подсудности. 5. Система отображает пользователю список доступных судов для передачи. 6. Судья выбирает суд для передачи и подтверждает выбор. 7. Система сохраняет выбранный суд для передачи в данных дела. 8. Система отображает подтверждение сохранения. |
| Расширение (альтернативный сценарий) | 2а. Система не может определить вид спора из-за отсутствующих данных и отображает перечень недостающих сведений. 2а1. Судья заполняет недостающие сведения. 2а2. Система определяет вид спора на основании обновленных данных и отображает результат. 2а3. Система формирует список доступных судов для передачи по подсудности. 2а4. Система отображает пользователю список доступных судов для передачи. 4а. Судья отменяет выбор суда. 4а1. Система не сохраняет изменения. |

UC 002: Принятие судебного акта по вопросу передачи по подсудности (Определение о передаче дела на рассмотрение СОЮ / другого АС)

|  |  |
| --- | --- |
| **Поле** | **Значение** |
| **№ шага процесса** | 7 |
| **Выполняемая задача** | Принять судебный акт по вопросу передачи дела по подсудности (определение о передаче). |
| **Цель** | Зафиксировать судебный акт о передаче дела по подсудности. |
| **Роль (в соответствии со схемой)** | Судья |
| **Ожидаемый результат** | Определение о передаче дела по подсудности сохранено в деле и имеет статус «Вынесено/Подписано». |
| **Рекомендованная функциональность** | Форма подготовки определения; предзаполнение реквизитов дела и выбранного суда; контроль обязательных полей; сохранение версии документа; фиксация даты вынесения; журналирование. |
| **Критичность** | необходимая |
| **Триггер** | Судья инициирует действие «Принять определение о передаче дела по подсудности». |
| **Предварительные условия** | В деле выбран суд для передачи; у судьи есть права на вынесение определения; карточка дела доступна для редактирования. |
| **Основной сценарий** | 1. Судья инициирует действие «Принять определение о передаче дела по подсудности». 2. Система открывает форму определения. 3. Система заполняет доступные реквизиты дела и выбранного суда. 4. Судья заполняет или корректирует реквизиты определения. 5. Судья нажимает «Подписать». 6. Система выполняет проверку заполнения обязательных полей. 7. Система сохраняет определение в деле. 8. Система фиксирует дату вынесения. 9. Система отображает статус «Вынесено/Подписано». |
| **Расширение (альтернативный сценарий)** | 6а. Система выявляет незаполненные обязательные реквизиты и отображает сообщения об ошибках. 6а1. Судья заполняет обязательные реквизиты. 6а2. Судья нажимает «Подписать». 6а3. Система выполняет проверку заполнения обязательных полей. 6а4. Система сохраняет определение в деле. 6а5. Система фиксирует дату вынесения. 6а6. Система отображает статус «Вынесено/Подписано». |

UC 003: Процесс направления дела по подсудности (с учетом проверки обжалования, включая ветку отмены определения вышестоящим судом)

|  |  |
| --- | --- |
| **Поле** | **Значение** |
| **№ шага процесса** | 8 - 18 |
| **Выполняемая задача** | Проконтролировать обжалование определения о передаче дела по подсудности и зафиксировать результат контроля. |
| **Цель** | Определить, отменено ли определение о передаче по подсудности, либо подтверждено, что оно не обжаловано или оставлено без изменения. |
| **Роль (в соответствии со схемой)** | Судья |
| **Ожидаемый результат** | В системе зафиксирован результат контроля обжалования определения: не обжаловано, оставлено без изменения либо отменено. |
| **Рекомендованная функциональность** | Контроль сроков и статусов обжалования; фиксация сведений об обжаловании и итогах рассмотрения; блокировка направления до результата; фиксация отмены определения; уведомления; журналирование. |
| **Критичность** | необходимая |
| **Триггер** | Судья инициирует действие «Проверить факт обжалования определения о передаче». |
| **Предварительные условия** | Определение о передаче вынесено и сохранено в деле; выбран суд для передачи; у судьи есть права на просмотр сведений об обжаловании и подтверждение результата. |
| **Основной сценарий** | 1. Судья инициирует действие «Проверить факт обжалования определения о передаче».  2. Система фиксирует начало отсчета срока обжалования определения.  3. Система выполняет проверку наличия сведений об обжаловании определения.  4. Система отображает судье результат проверки: сведения об обжаловании отсутствуют.  5. Судья подтверждает результат проверки в интерфейсе системы.  6. Система фиксирует подтверждение результата проверки.  7. Система отображает признак, что определение может быть использовано для подготовки передачи дела. |
| **Расширение (альтернативный сценарий)** | 3а. Система отображает судье результат проверки: сведения об обжаловании имеются.  3а1. Система фиксирует статус ожидания итогов рассмотрения жалобы вышестоящим судом.  3а2. Система получает сведения об итогах рассмотрения жалобы.  3а3. Система уведомляет судью о поступлении итогов рассмотрения жалобы.  3а4. Судья открывает сведения об итогах рассмотрения жалобы в системе.  3а5. Судья подтверждает результат рассмотрения жалобы.  3а6. Система фиксирует результат: определение оставлено без изменения.  3а7. Система отображает признак, что определение может быть использовано для подготовки передачи дела.  3б. Система получает сведения об итогах рассмотрения жалобы.  3б1. Система отображает судье результат: определение отменено.  3б2. Судья подтверждает результат отмены определения.  3б3. Система фиксирует невозможность передачи дела по подсудности в связи с отменой определения.  3б4. Система отображает завершение сценария по негативной ветке. |
