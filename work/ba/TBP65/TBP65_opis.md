| **Наименование процесса** | ТБП65: Передать дело по подсудности |
| **Суть процесса** | Процесс определяет порядок принятия судебного решения о передаче дела на рассмотрение другого арбитражного суда или суда общей юрисдикции при выявлении нарушений правил подсудности или при наличии иных установленных законом оснований (ст. 39 АПК РФ). Судья проводит комплексную проверку оснований для передачи с использованием автоматизированных проверок системы, валидирует полученные результаты и принимает обоснованное решение о передаче дела или отказе в удовлетворении соответствующего ходатайства. После вынесения судебного определения система обеспечивает ознакомление участников дела с решением, контролирует сроки обжалования и организует направление дела в суд-адресат. |
| **Участники процесса** | Судья |
| **НПА** | АПК РФ (Арбитражный процессуальный кодекс Российской Федерации)  Постановление Пленума Верховного Суда РФ от 04.06.2024 N 12 "О подготовке дела к судебному разбирательству в арбитражном суде"  Постановление Пленума Верховного Суда РФ от 23.12.2021 N 46 "О применении Арбитражного процессуального кодекса Российской Федерации при рассмотрении дел в суде первой инстанции" |

UC-001: Автоматическая проверка оснований передачи по подсудности

|  |  |

| Цель | Снизить ручную нагрузку и риск ошибок при оценке подсудности, обеспечить прозрачный результат проверки для последующего вынесения судебного акта. |

| Рекомендованная функциональность | Автопроверки по данным дела, формирование выводов и рекомендаций, чек-лист валидации пользователем, контроль заполнения обязательных данных, журналирование, уведомления о необходимости валидации, хранение версии результата проверки. |
| Критичность | Высокая |

| Предварительные условия | Дело зарегистрировано в системе, внесены ключевые сведения, влияющие на подсудность, у пользователя есть права на запуск и валидацию проверки. |
| Основной сценарий | 1. Пользователь запускает проверку оснований передачи по подсудности. 2. Система анализирует данные дела и формирует вывод: основания подтверждаются или не подтверждаются, с указанием используемых данных дела. 3. Система отображает выводы и предоставляет интерфейс валидации. 4. Пользователь валидирует выводы системы. 5. Система фиксирует результат валидации и сохраняет версию результата проверки. 6. Возникает технический сбой при выполнении проверки. Система фиксирует ошибку, выполняет повторную попытку и уведомляет пользователя при невозможности завершить проверку. |

| **Ожидаемый результат** | При отсутствии препятствий дело направлено в другой суд и зафиксирована доставка. При отмене определения вышестоящим судом направление остановлено или выполнены действия по обработке отмены. |

| **Основной сценарий** | 1. Система проверяет результат проверки обжалования и определяет возможность направления дела. 2. Канцелярия формирует направление и пакет на отправку в другой суд. 3.
