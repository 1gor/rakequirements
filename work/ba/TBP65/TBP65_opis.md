# [To be] ТБП65. Передать дело по подсудности

| **Наименование процесса** | ТБП65: Передать дело по подсудности |
| --- | --- |
| **Суть процесса** | Процесс начинается с момента, когда судом выявляется нарушение территориальной, родовой либо иной подсудности, а также при выявлении иных предусмотренных законом оснований для передачи по подсудности. В рамках процесса судья определяет надлежащий арбитражный суд или надлежащий СОЮ, уполномоченный на рассмотрение дела, и принимает судебный акт о передаче дела по подсудности. После вынесения определения обеспечивается его подписание, приобщение к материалам дела и направление копий лицам, участвующим в деле. По истечении срока 10 дней; срок на обжалование определения в апелляционном суде, осуществляется подготовка материалов дела к передаче: формирование и проверка состава дела, оформление в соответствии с требованиями делопроизводства, регистрация передачи в информационной системе суда и фактическое направление дела в соответствующий арбитражный суд или СОЮ. Процесс завершается передачей дела по подсудности в другой суд или оставлением его в производстве данного суда в связи с отменой вышестоящим судом определения о передаче по подсудности |
| **Участники процесса** | Судья |
| **НПА** | АПК РФ (Арбитражный процессуальный кодекс Российской Федерации)  Постановление Пленума Верховного Суда РФ от 04.06.2024 N 12 "О подготовке дела к судебному разбирательству в арбитражном суде"  Постановление Пленума Верховного Суда РФ от 23.12.2021 N 46 "О применении Арбитражного процессуального кодекса Российской Федерации при рассмотрении дел в суде первой инстанции" |

Стартовое событие наступает после того, как при рассмотрении дела установлены предусмотренные законом основания для его передачи в другой суд. Такими основаниями могут быть случаи передачи дела в другой арбитражный суд того же уровня, предусмотренные частью 2 статьи 39 АПК РФ, либо установление того, что дело подлежит рассмотрению судом общей юрисдикции в порядке части 4 статьи 39 АПК РФ. С момента фиксации основания запускается процесс автоматизированного анализа дела и определения суда, которому оно должно быть передано. | Не выявлено |

В рамках анализа Система определяет, относится ли установленное основание к передаче дела в суд общей юрисдикции либо к передаче в другой арбитражный суд того же уровня, а также фиксирует сведения, которые будут использованы при выборе конкретного суда-адресата. Если основание относится к случаям части 2 статьи 39 АПК РФ, Система формирует признак передачи в другой арбитражный суд того же уровня. В ходе подпроцесса фиксируются способ, дата и реквизиты отправки, а при электронной передаче — сведения о доставке электронных материалов. Дополнительное описание: После получения подтверждения о выполненном направлении Система автоматически изменяет текущий статус дела с «Передано судье», «Подготовка к рассмотрению» или «Рассмотрение» на «Передано по подсудности». ## **3.**Реестр UC (в части выполняемых пользователем задач **и рекомендованной функциональности Системы)**

UC 001: Выбор суда для передачи по подсудности (в зависимости от вида спора; СОЮ или Арбитраж)

| Поле | Значение |
| --- | --- |
| № шага процесса | 0 - 6 |
| Выполняемая задача | Выбрать суд для передачи дела по подсудности (СОЮ или арбитражный суд). |
| Цель | Определить суд, в который подлежит передача дела по подсудности. |
| Роль (в соответствии со схемой) | Судья |
| Ожидаемый результат | В карточке дела зафиксирован выбранный суд для передачи по подсудности. |
| Рекомендованная функциональность | Определение вида спора по данным дела; подбор суда для передачи (СОЮ/АС); отображение доступных вариантов; сохранение выбранного суда в данных дела; журналирование действий. |
| Критичность | необходимая |
| Триггер | Судья инициирует действие «Передать дело по подсудности» в карточке дела. |
| Предварительные условия | Открыта карточка дела; у судьи есть права на запуск передачи по подсудности; в деле заполнены сведения, позволяющие определить вид спора. |
| Основной сценарий | 1. Судья инициирует действие «Передать дело по подсудности». 2. Система определяет вид спора на основании данных дела. 3. Система отображает судье результат определения вида спора. 4. Система формирует список доступных судов для передачи по подсудности. 5. Система отображает судье список доступных судов для передачи. 6. Судья выбирает суд для передачи из списка. 7. Судья подтверждает выбор суда (нажимает «Подтвердить»). 8. Система сохраняет выбранный суд для передачи в данных дела. 9. Система отображает подтверждение сохранения. |
| Расширение (альтернативный сценарий) | 2а. Система не может определить вид спора из-за отсутствующих данных и отображает перечень недостающих сведений. 2а1. Судья заполняет недостающие сведения. 2а2. Судья сохраняет внесенные сведения (нажимает «Сохранить»/«Продолжить»). 2а3. Система определяет вид спора на основании обновленных данных и отображает результат. 2а4. Система формирует список доступных судов для передачи по подсудности. 2а5. Система отображает судье список доступных судов для передачи. 6а. Судья отменяет выбор суда на экране выбора суда для передачи. 6а1. Система не сохраняет изменения. |

UC 002: Принятие судебного акта по вопросу передачи по подсудности (Определение о передаче дела на рассмотрение СОЮ / другого АС)

| Поле | Значение |
| --- | --- |
| № шага процесса | 7 |
| Выполняемая задача | Принять судебный акт по вопросу передачи дела по подсудности (определение о передаче). |
| Цель | Зафиксировать судебный акт о передаче дела по подсудности. |
| Роль (в соответствии со схемой) | Судья |
| Ожидаемый результат | Определение о передаче дела по подсудности сохранено в деле и имеет статус «Вынесено/Подписано». |
| Рекомендованная функциональность | Форма подготовки определения; предзаполнение реквизитов дела и выбранного суда; контроль обязательных полей; сохранение версии документа; фиксация даты вынесения; журналирование. |
| Критичность | необходимая |
| Триггер | Судья инициирует действие «Принять определение о передаче дела по подсудности». |
| Предварительные условия | В деле выбран суд для передачи; у судьи есть права на вынесение определения; карточка дела доступна для редактирования. |
| Основной сценарий | 1. Судья инициирует действие «Принять определение о передаче дела по подсудности». 2. Система открывает форму определения. 3. Система заполняет доступные реквизиты дела и выбранного суда. 4. Судья заполняет или корректирует реквизиты определения. 5. Судья нажимает «Подписать». 6. Система выполняет проверку заполнения обязательных полей. 7. Система сохраняет определение в деле. 8. Система фиксирует дату вынесения в реквизите определения (дата = дата подписания). 9. Система присваивает определению статус «Вынесено/Подписано». 10. Система отображает присвоенный статус в карточке дела. |
| Расширение (альтернативный сценарий) | 6а. Система выявляет незаполненные обязательные реквизиты и отображает сообщения об ошибках. 6а1. Судья заполняет обязательные реквизиты. 6а2. Судья нажимает «Подписать». 6а3. Система выполняет проверку заполнения обязательных полей. 6а4. Система сохраняет определение в деле. 6а5. Система фиксирует дату вынесения в реквизите определения (дата = дата подписания). 6а6. Система присваивает определению статус «Вынесено/Подписано». 6а7. Система отображает присвоенный статус в карточке дела. |

UC 003: Процесс направления дела по подсудности (с учетом проверки обжалования, включая ветку отмены определения вышестоящим судом)

| Поле | Значение |
| --- | --- |
| № шага процесса | 8 - 18 |
| Выполняемая задача | Проконтролировать обжалование определения о передаче дела по подсудности и зафиксировать результат контроля. |
| Цель | Определить, отменено ли определение о передаче по подсудности, либо подтверждено, что оно не обжаловано или оставлено без изменения. |
| Роль (в соответствии со схемой) | Судья |
| Ожидаемый результат | В системе зафиксирован результат контроля обжалования определения: не обжаловано, оставлено без изменения либо отменено. |
| Рекомендованная функциональность | Контроль сроков и статусов обжалования; фиксация сведений об обжаловании и итогах рассмотрения; блокировка направления до результата; фиксация отмены определения; уведомления; журналирование. |
| Критичность | необходимая |
| Триггер | Судья инициирует действие «Проверить факт обжалования определения о передаче». |
| Предварительные условия | Определение о передаче вынесено и сохранено в деле; выбран суд для передачи; у судьи есть права на просмотр сведений об обжаловании и подтверждение результата. |
| Основной сценарий | 1. Судья инициирует действие «Проверить факт обжалования определения о передаче». 2. Система отображает в карточке определения дату начала и дату окончания срока обжалования (10 дней) и статус «Идет срок обжалования». 3. Система выполняет проверку наличия сведений об обжаловании определения. 4. Система отображает судье результат проверки: сведения об обжаловании отсутствуют. 5. Судья подтверждает результат проверки (нажимает «Подтвердить результат»). 6. Система фиксирует подтверждение результата проверки (журналирование/признак «Обжалование не поступило»). 7. Система отображает признак, что определение может быть использовано для подготовки передачи дела. |
| Расширение (альтернативный сценарий) | 3а. Система отображает судье результат проверки: сведения об обжаловании имеются. 3а1. Система устанавливает статус «Ожидаются итоги рассмотрения жалобы» и отображает его. 3а2. Система получает сведения об итогах рассмотрения жалобы. 3а3. Система уведомляет судью о поступлении итогов рассмотрения жалобы. 3а4. Судья открывает сведения об итогах рассмотрения жалобы в системе. 3а5. Судья подтверждает результат рассмотрения жалобы (нажимает «Подтвердить»). 3а6. Система фиксирует результат: определение оставлено без изменения. 3а7. Система отображает признак, что определение может быть использовано для подготовки передачи дела.  3б. В полученных сведениях об итогах рассмотрения жалобы указано, что определение отменено. 3б1. Судья подтверждает результат отмены определения (нажимает «Подтвердить»). 3б2. Система фиксирует отмену определения и устанавливает в карточке дела признак «Передача по подсудности невозможна». 3б3. Система отображает уведомление о завершении сценария по негативной ветке. |
