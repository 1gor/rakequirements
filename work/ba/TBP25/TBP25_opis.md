# [To be] ТБП25. Проверить льготы по госпошлине

| **Наименование процесса** | ТБП25 — Проверить льготы по госпошлине |
| --- | --- |
| **Суть процесса** | Процесс предназначен для проверки наличия оснований для освобождения от уплаты государственной пошлины. Система на основании данных карточки дела и материалов, поступивших в суд, определяет категорию спора и категорию лица, формирует проверяемые результаты и передает их в ТБП139 «Проверить выводы системы». Для инвалидов I и II группы и общественных организаций инвалидов дополнительно проверяются характер и цена исковых требований. При необходимости Система проверяет наличие документа, подтверждающего право на льготу; при его отсутствии вызывается ТБП34 «Рассмотреть вопрос об оставлении без движения». Результатом ТБП25 является зафиксированная категория освобождения либо результат об отсутствии установленных оснований для освобождения в пределах логики текущей схемы. |
| **Участники процесса** | Помощник судьи; Система |
| **НПА** | Налоговый кодекс Российской Федерации (часть вторая) от 05.08.2000 № 117-ФЗ: ст. 333.21, 333.37.  Арбитражный процессуальный кодекс Российской Федерации от 24.07.2002 № 95-ФЗ: ст. 105, п. 2 ч. 1 ст. 126, ст. 128, 129. |

| 1 | Определить категорию спора | **Тип:** Сервисная задача  **Назначение:** Автоматически определить категорию спора, значимую для проверки льгот по госпошлине.  **Роль:** Система  **Входящие данные:** Материалы дела; сведения о предмете спора и заявленных требованиях; данные карточки дела  **Исходящие данные:** Определенная категория спора; применимое основание проверки  **Описание:** Система сопоставляет сведения о предмете спора и заявленных требованиях с настроенными правилами классификации категорий, для которых законодательством предусмотрены льготы по уплате государственной пошлины. В результате фиксируются определенная категория спора, использованные исходные данные и соответствующее основание проверки.  **Результат шага:** Категория спора определена и подготовлена для включения в протокол проверки. | — |
| 2 | Определить категорию лица | **Тип:** Сервисная задача  **Назначение:** Автоматически определить принадлежность лица к категориям, значимым для проверки льгот по госпошлине.  **Роль:** Система  **Входящие данные:** Сведения о лице из карточки дела и поступившего документа: тип лица, процессуальное положение, доступные сведения о статусе  **Исходящие данные:** Определенная категория лица; применимое основание проверки  **Описание:** Система сопоставляет сведения о лице и его процессуальном положении с категориями лиц, предусмотренными правилами проверки льгот. Результат должен содержать определенную категорию либо признак отсутствия соответствующей категории, а также основание, по которому выполнено сопоставление.  **Результат шага:** Категория лица определена и подготовлена для включения в протокол проверки. | — |
| 3 | Сформировать протокол проверки | **Тип:** Сервисная задача  **Назначение:** Сформировать проверяемый результат автоматического определения категории спора и категории лица.  **Роль:** Система  **Входящие данные:** Определенная категория спора; определенная категория лица; исходные данные и примененные правила шагов 1–2  **Исходящие данные:** Протокол проверки категории спора и категории лица  **Описание:** Система формирует протокол, содержащий исходные сведения, определенные категории, примененные правила/основания и результат каждой проверки. Протокол используется как вход ТБП139 и должен позволять помощнику судьи понять, на основании каких данных получен автоматический вывод.  **Результат шага:** Сформирован протокол проверки категории спора и категории лица. | — |
| 4 | [<u>ТБП139.Проверить выводы системы</u>](https://itpm-wiki.mos.ru/pages/viewpage.action?pageId=533163178) | **Тип:** Вызов активности  **Назначение:** Передать результаты автоматической классификации на проверку.  **Роль:** Помощник судьи  **Входящие данные:** Протокол проверки категории спора и категории лица  **Исходящие данные:** Проверенный и при необходимости скорректированный результат определения категории спора и категории лица  **Описание:** Вызывается ТБП139 «Проверить выводы системы». ## **3. Реестр UC**

**UC001 — Проверка категории спора и категории лица**

| **№ шага процесса** | 0–10 |
| --- | --- |
| **Выполняемая задача** | Проверка оснований льготы по категории спора и категории лица |
| **Цель** | Получить проверенный результат автоматической классификации и определить дальнейший маршрут проверки льготы. |
| **Роль / Актор** | Помощник судьи |
| **Ожидаемый результат** | Определено, имеется ли основание освобождения по категории спора или лица; результат автоматической классификации проверен. |
| **Рекомендуемая функциональность** | Автоматическое определение категории спора и лица по структурированным данным дела; формирование протокола с исходными данными, примененными правилами и результатом. |
| **Критичность** | Необходима |
| **Триггер** | Из вызывающего процесса в ТБП25 переданы материалы дела и команда на выполнение проверки льготы по государственной пошлине. |
| **Предварительные условия** | Материалы дела и сведения о лице зарегистрированы и доступны Системе; помощник судьи авторизован. |
| **Основной сценарий** | 1. Система получает материалы дела и сведения о лице. 2. Система определяет категорию спора и фиксирует использованные данные и применимое правило. 3. Система определяет категорию лица с учетом его процессуального положения. 4. Система формирует протокол проверки категории спора и категории лица. 5. Протокол передается в ТБП139 «Проверить выводы системы». 6. После возврата проверенного результата Система выбирает ветвь по категории спора. 7. При наличии основания по категории спора Система фиксирует категорию освобождения; при его отсутствии проверяется категория лица. 8. Если основание не установлено ни по категории спора, ни по категории лица, Система формирует служебное уведомление помощнику судьи и процесс завершается отрицательным результатом. |
| **Расширение (альтернативный сценарий)** | 1. Если в ТБП139 помощник судьи корректирует определенную Системой категорию спора или лица, в дальнейшей маршрутизации используется скорректированное значение. 2. Если после корректировки устанавливается основание освобождения, процесс продолжает соответствующую положительную ветвь. |

| **Предварительные условия** | Категория лица подтверждена; исковое заявление и сведения о заявленных требованиях доступны Системе. |
| **Основной сценарий** | 1. Система определяет характер исковых требований. 2. Система получает цену иска из карточки дела и/или заявления. 3. Система формирует протокол проверки характера и цены требований с указанием исходных данных и примененных правил. 4. Протокол передается в ТБП139 «Проверить выводы системы». 5. После возврата проверенного результата Система проверяет соответствие характера требований условию п. 3 ст. 333.37 НК РФ. 6. При соответствии выполняется стоимостная проверка и процесс переходит к предусмотренной BPMN ветви. |
| **Расширение (альтернативный сценарий)** | 1. Если ТБП139 возвращает скорректированный характер требований или цену иска, дальнейшие проверки выполняются по скорректированным значениям. 2. Если характер требований не соответствует условию п. 3 ст. 333.37 НК РФ, процесс переходит в отрицательную ветвь. 3. Для цены иска свыше 1 000 000 руб. текущая BPMN требует доработки: по п. 3 ст. 333.37 НК РФ применяется уменьшенная пошлина, а не полное отсутствие льготы. |

**UC003 — Проверка подтверждающего документа и фиксация льготы**

| **№ шага процесса** | 12–13, 23–36 |
| --- | --- |
| **Выполняемая задача** | Проверка подтверждающего документа и фиксация результата льготы |
| **Цель** | Подтвердить право на льготу документом, если такое подтверждение требуется, и зафиксировать итог проверки. |
| **Роль / Актор** | Помощник судьи |
| **Ожидаемый результат** | Категория освобождения зафиксирована и проверена либо сформирован отрицательный результат из-за непредставления требуемого документа. |
| **Рекомендуемая функциональность** | Автоматическое определение необходимости документа; проверка его наличия по составу материалов дела; служебное уведомление; ожидание поступления документа или истечения срока. |
| **Критичность** | Необходима |
| **Триггер** | В ТБП25 получен результат предыдущих проверок, по которому требуется определить наличие документального подтверждения права на льготу. |
| **Предварительные условия** | Категория лица и применимое основание льготы определены; сведения о составе документов дела доступны Системе. |
| **Основной сценарий** | 1. Система определяет, требуется ли отдельный подтверждающий документ. 2. Если документ не требуется, процесс переходит к фиксации категории освобождения. 3. Если документ требуется, Система проверяет его наличие среди материалов дела. 4. При наличии документа процесс переходит к фиксации категории освобождения. 5. Система заполняет категорию освобождения и передает сформированную запись в ТБП139 «Проверить выводы системы». 6. После возврата проверенного результата процесс завершается фиксацией установленного основания освобождения. |
| **Расширение (альтернативный сценарий)** | 1. Если требуемый документ отсутствует, Система формирует служебное уведомление помощнику судьи и вызывается ТБП34 «Рассмотреть вопрос об оставлении без движения». 2. После получения определения и установленного срока процесс ожидает первое событие: поступление документа или истечение срока. 3. Если документ поступил до истечения срока, процесс продолжает фиксацию категории освобождения. 4. Если срок истек раньше поступления документа, ТБП25 завершается результатом «право на льготу не подтверждено требуемым документом»; последующие действия с заявлением выполняются вне ТБП25. |
