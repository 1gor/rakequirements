# [To be] ТБП41. Провести возврат госпошлины

| **Наименование процесса** | ТБП41 — Провести возврат госпошлины |
| --- | --- |
| **Суть процесса** | Процесс предназначен для автоматизированной проверки предусмотренного схемой платежного документа, выявления возможного повторного использования документа, расчета суммы государственной пошлины и подготовки структурированного результата проверки. При отсутствии платежного документа либо выявлении дубля Система формирует протокол проверки, который передается в ТБП139 «Проверить выводы системы». По основной ветви либо после возврата результата ТБП139 Судья выбирает способ процессуального оформления: отдельным судебным актом через ТБП80 «Принять СА» либо в ином судебном акте. Принятый отдельный судебный акт направляется заявителю через ТБП46 «Направить документ». Фактическое перечисление денежных средств плательщику в BPMN ТБП41 не моделируется. |
| **Участники процесса** | Судья; Канцелярия; Система |
| **НПА** | Арбитражный процессуальный кодекс Российской Федерации от 24.07.2002 № 95-ФЗ: ст. 104. Налоговый кодекс Российской Федерации (часть вторая) от 05.08.2000 № 117-ФЗ: ст. 333.18, 333.40. Постановление Пленума Верховного Суда Российской Федерации от 23.12.2025 № 39 «О некоторых вопросах уплаты государственной пошлины при рассмотрении дел в судах»: п. 6, 8, 12, 13. |

| 1 | Проверить наличие платежного документа в деле | **Тип:** Сервисная задача **Назначение:** Автоматически проверить наличие предусмотренного схемой платежного документа в материалах текущего дела. **Роль:** Система **Входящие данные:** Принятое заявление о возврате государственной пошлины; материалы дела; сведения о документах текущего дела. **Исходящие данные:** Статус поиска «платежный документ найден / не найден»; найденный платежный документ и его идентифицирующие реквизиты — при наличии. **Описание:** Система проверяет состав документов текущего дела на наличие платежного документа, связанного с уплатой государственной пошлины по рассматриваемому обращению. Если такой документ обнаружен, Система фиксирует статус «найден» и передает документ с его реквизитами на шаг 3; при отсутствии документа фиксируется статус «не найден». Статус используется шлюзом на шаге 2. **Результат шага:** Сформирован однозначный результат проверки наличия платежного документа. | — |

При статусе «платежный документ не найден» выбирается ветвь «Нет» и переход к шагу 7, после чего формируется протокол проверки. **Результат шага:** Выбран маршрут дальнейшей проверки по результату шага 1. | — |
| 3 | Проверить платежный документ на дубли в других делах | **Тип:** Сервисная задача **Назначение:** Автоматически проверить найденный платежный документ на совпадение с платежными документами, учтенными в других делах. **Роль:** Система **Входящие данные:** Найденный платежный документ; его идентифицирующие реквизиты; доступные Системе сведения о платежных документах, учтенных в других делах. **Исходящие данные:** Статус проверки «дубль найден / дубль не найден»; перечень найденных совпадений и сведения о соответствующих делах — при наличии. **Описание:** Система сопоставляет идентифицирующие реквизиты найденного платежного документа с реквизитами платежных документов, учтенных в других делах. При наличии совпадения фиксируется статус «дубль найден» и сохраняются сведения о совпадениях; при отсутствии совпадений — статус «дубль не найден». Результат используется шлюзом на шаге 4. **Результат шага:** Сформирован проверяемый результат сопоставления платежного документа с данными других дел. | — |
| 4 | Найден дубль? | **Тип:** Эксклюзивный шлюз **Назначение:** Выбрать маршрут по статусу проверки на повторное использование платежного документа. **Роль:** — **Входящие данные:** Статус шага 3 «дубль найден / дубль не найден»; сведения о найденных совпадениях — при наличии. **Исходящие данные:** Маршрут «Да» или «Нет». **Описание:** При статусе «дубль найден» выбирается ветвь «Да» и переход к шагу 7, после чего формируется протокол проверки. При статусе «дубль не найден» выбирается ветвь «Нет» и переход к расчету на шаге 5. **Результат шага:** Выбран маршрут дальнейшего процесса по результату проверки на дубли. | — |

Сервисная задача формирует расчетный результат и сама по себе не устанавливает отдельный юридический вывод о наличии правового основания возврата. После завершения ТБП80 принятый судебный акт передается на шаг 15. **Результат шага:** Получен предусмотренный схемой отдельный судебный акт по вопросу возврата государственной пошлины. | — |
| 15 | [<u>ТБП46.Направить документ</u>](https://itpm-wiki.mos.ru/pages/viewpage.action?pageId=533163557) | **Тип:** Вызов активности **Назначение:** Передать принятый отдельный судебный акт для направления истцу/заявителю. **Роль:** Канцелярия **Входящие данные:** Принятый судебный акт по вопросу возврата государственной пошлины; сведения об истце/заявителе из принятого заявления и материалов дела. **Исходящие данные:** Результат ТБП46: документ направлен адресату. **Описание:** Канцелярия вызывает ТБП46 «Направить документ» и передает принятый судебный акт вместе со сведениями об адресате, полученными из входных материалов ТБП41. Значимым возвращаемым результатом является факт направления документа адресату. После завершения ТБП46 процесс переходит к шагу 16. **Результат шага:** Получен результат направления отдельного судебного акта истцу/заявителю. | — |
| 16 | Вынесено определение по вопросу возврата госпошлины. Определение направлено истцу/заявителю | **Тип:** Конечное событие **Назначение:** Зафиксировать завершение ветви после принятия и направления отдельного судебного акта. **Роль:** — **Входящие данные:** Принятый судебный акт; результат ТБП46 о направлении документа истцу/заявителю. **Исходящие данные:** Результат ТБП41: отдельный судебный акт по вопросу возврата государственной пошлины принят и направлен истцу/заявителю. **Описание:** Процесс завершается после возврата из ТБП46 результата о направлении принятого судебного акта. Конечное событие фиксирует два наблюдаемых факта: судебный акт принят и его направление адресату выполнено. **Результат шага:** Ветка ТБП41 завершена принятием и направлением отдельного судебного акта. | — |

# **3. Реестр UC**

**UC001 — Получение результата автоматизированной проверки и выбор способа оформления**

| № шага процесса | 0–14 |
| --- | --- |
| Выполняемая задача | Получение Судьей результата автоматизированной проверки и выбор способа процессуального оформления. |
| Цель | Предоставить Судье структурированный и проверяемый результат автоматизированной обработки данных по вопросу возврата государственной пошлины и зафиксировать решение о способе его процессуального оформления. |
| Роль / Актор | Судья |
| Ожидаемый результат | Судье доступна рекомендация по сумме государственной пошлины либо проверенный в ТБП139 отрицательный результат; выбран способ процессуального оформления; при выборе отдельного судебного акта ТБП80 вернул принятое определение либо ветвь завершена со статусом оформления результата в ином судебном акте. |
| Рекомендуемая функциональность | Автоматическая проверка наличия платежного документа и дублей; расчет суммы и формирование рекомендации; формирование протокола отрицательной проверки и передача его в ТБП139; отображение Судье результата с исходными данными; фиксация выбранного способа оформления и маршрутизация в ТБП80 либо к конечному событию 13. |
| Критичность | Необходима |
| Триггер | ТБП40 «Рассмотреть заявление о возврате госпошлины» передал в ТБП41 принятое заявление, материалы дела и результат ТБП15 «заявление принято». |
| Предварительные условия | Принятое заявление, материалы дела и сведения о документах доступны Системе; Судья авторизован и может получить результат автоматизированной проверки на пользовательской задаче 11. |
| Основной сценарий | 1. Система проверяет наличие платежного документа и фиксирует результат «найден / не найден».  2. Если документ найден, Система проверяет его на дубли в других делах.  3. При отсутствии дублей Система рассчитывает сумму государственной пошлины и формирует рекомендацию с исходными значениями и результатами предшествующих проверок.  4. Рекомендация передается Судье на пользовательскую задачу 11.  5. Судья знакомится с результатом и исходными данными и выбирает вариант «необходимо вынести отдельный СА».  6. Система фиксирует выбор и направляет процесс в ТБП80 «Принять СА».  7. После завершения ТБП80 в ТБП41 возвращается принятое определение. |
| Расширение (альтернативный сценарий) | 1. Если платежный документ не найден, Система формирует протокол с исходными данными и результатом проверки и передает его в ТБП139 «Проверить выводы системы».  2. Если найден дубль, Система формирует протокол со сведениями о совпадениях и также передает его в ТБП139.  3. В ТБП139 Судья проверяет выводы Системы и при необходимости корректирует результат; подтвержденный либо скорректированный результат возвращается в ТБП41 и становится доступен Судье на шаге 11.  4. Судья выбирает способ процессуального оформления с учетом полученного результата.  5. Если отдельный судебный акт не требуется, процесс завершается на шаге 13 со статусом оформления результата в ином судебном акте.  6. Если отдельный судебный акт требуется, вызывается ТБП80; в зависимости от результата предшествующей ветви возвращается определение о полном/частичном возврате либо определение об отказе. |

**UC002 — Направление отдельного судебного акта заявителю**

| № шага процесса | 15–16 |
| --- | --- |
| Выполняемая задача | Передача принятого отдельного судебного акта в ТБП46 «Направить документ» и получение результата направления. |
| Цель | Передать принятый судебный акт и сведения об адресате в типовой процесс направления и зафиксировать завершение ветви после возврата результата. |
| Роль / Актор | Канцелярия |
| Ожидаемый результат | Получен результат ТБП46 «Направить документ» о направлении принятого судебного акта истцу/заявителю; ветвь ТБП41 завершена. |
| Рекомендуемая функциональность | Передача судебного акта и сведений об адресате в ТБП46 «Направить документ» с получением возвращаемого результата направления. |
| Критичность | Необходима |
| Триггер | ТБП80 «Принять СА» вернул принятый отдельный судебный акт по вопросу возврата государственной пошлины. |
| Предварительные условия | Судебный акт принят; сведения об истце/заявителе доступны из входного заявления и материалов дела. |
| Основной сценарий | 1. Канцелярия инициирует ТБП46 «Направить документ».  2. В ТБП46 передаются принятый судебный акт и сведения об истце/заявителе.  3. После завершения ТБП46 в ТБП41 возвращается результат «документ направлен адресату».  4. ТБП41 завершается на шаге 16 с результатом о принятии и направлении отдельного судебного акта. |
| Расширение (альтернативный сценарий) | 1. Внутренние варианты направления и обработка ошибок относятся к логике ТБП46 «Направить документ» и в UC ТБП41 не дублируются.  2. Иных ветвей после возврата результата ТБП46 текущая BPMN ТБП41 не содержит. |
