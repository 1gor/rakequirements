TBP11: Рассмотреть заявление об ускорении рассмотрения дела To Be

|  |  |
| --- | --- |
| Наименование процесса | TBP11: Рассмотреть заявление об ускорении рассмотрения дела |
| Суть процесса | Рассмотрение заявления лица, участвующего в деле, об ускорении судебного разбирательства в целях соблюдения права на судопроизводство. Суд (обычно председатель) анализирует обоснованность заявления, выносит определение об удовлетворении или отказе и, при необходимости, принимает меры по ускорению рассмотрения дела. |
| Участники процесса | Судья, Председатель, Канцелярия, Лицо, участвующее в деле |
| НПА | Арбитражный процессуальный кодекс Российской Федерации от 24.07.2002 N 95-ФЗ (ред. от 01.04.2025)  Федеральный закон от 30.04.2010 № 68-ФЗ «О компенсации за нарушение права на судопроизводство в разумный срок» |

2.1. Схема процесса

**3. Реестр UC (в части выполняемых пользователем задач и рекомендованной функциональности Системы)**UC-001. Подача документов в суд

|  |  |
| --- | --- |
| **№ шага процесса** | 0-2 |
| **Выполняемая задача** | Подать заявление об ускорении рассмотрения дела в суд (в рамках типового процесса «Подать документы в суд»). |
| **Цель** | Инициировать рассмотрение председателем суда вопроса об ускорении рассмотрения дела. |
| **Роль (в соответствии со схемой)** | Лицо, участвующее в деле |
| **Ожидаемый результат** | Заявление об ускорении рассмотрения дела подано в суд, факт подачи зафиксирован. |
| **Рекомендованная функциональность** | 1. Предоставление шаблонов/подсказок по заполнению заявления (при наличии).  2. Проверка полноты пакета перед отправкой (валидации обязательных полей/приложений).  3. Отображение статуса отправки и регистрационного признака подачи (если доступен). |
| **Критичность** | Высокая |
| **Триггер** | Возникла необходимость ускорить рассмотрение дела; принято решение подать заявление. |
| **Предварительные условия** | Пользователь идентифицирован; выбрано дело/контекст подачи; подготовлен текст заявления. |
| **Основной сценарий** | 1. Пользователь фиксирует необходимость ускорения рассмотрения дела.  2. Пользователь подает заявление об ускорении в суд через типовой процесс "Подать документы в суд".  3. Система фиксирует факт подачи и отображает статус "Заявление подано". |
| **Расширение (альтернативный сценарий)** | 2а. Пользователь прерывает подачу/не завершает отправку - заявление не считается поданным, статус "Черновик/Не отправлено".  2б. Выявлена неполнота/ошибка заполнения - система показывает сообщения об ошибках, пользователь корректирует данные и повторяет шаг 2. |

Статусы обработки: «поступило», «зарегистрировано», «передано по назначению».  3. Контроль полноты реквизитов регистрации и маршрутизация в рамках типового процесса приема. |

| **Основной сценарий** | 1. Канцелярия фиксирует поступление заявления.  2. Канцелярия регистрирует заявление через ТБП53 "Принять входящий документ" и направляет по назначению (председателю суда). |
| **Расширение (альтернативный сценарий)** | 2а. Регистрация невозможна (техническая ошибка/некорректный формат) - документ остается в статусе "Требует обработки"; повторить шаг 2 после устранения причины.  2б. Документ направлен ошибочно - выполнить перенаправление и зафиксировать действие в системе. |

UC-003. Рассмотрение вопроса об ускорении рассмотрения дела

|  |  |
| --- | --- |
| **№ шага процесса** | 5-10 |
| **Выполняемая задача** | Предоставить председателю доступ к материалам, обеспечить рассмотрение заявления и вынесение определения (удовлетворить/отказать), приобщить документы к делу и поставить судье задачу на ознакомление. |
| **Цель** | Принять юридически значимое решение по заявлению и обеспечить его доведение до судьи для исполнения. |
| **Роль (в соответствии со схемой)** | Председатель; Система |
| **Ожидаемый результат** | Вынесено определение по результатам рассмотрения; определение и заявление связаны с делом; судье поставлена задача на ознакомление. |
| **Рекомендованная функциональность** | 1. Автоматическое предоставление председателю доступа к делу/материалам (управление доступом).  2. Поддержка подготовки проекта определения по шаблону и удобное редактирование.  3. Автоматическая постановка связей «заявление - определение - дело».  4. Постановка задачи судье и уведомления о поступлении определения. |
| **Критичность** | Высокая |
| **Триггер** | Заявление зарегистрировано и передано по назначению; требуется рассмотрение председателем . |
| **Предварительные условия** | Председатель имеет полномочия и доступ; заявление и материалы дела доступны в системе; определен контекст дела для привязки документов. |
| **Основной сценарий** | 1. Система предоставляет председателю доступ к делу/документу.  2. Председатель знакомится с заявлением и материалами дела.  3. Председатель рассматривает вопрос об ускорении и принимает решение.  4. Председатель выносит определение (удовлетворение/отказ) в рамках ТБП80 "Принять СА".  5. Система проставляет связи между определением, заявлением и делом.  6. Система ставит судье задачу на ознакомление и направляет уведомление. |
| **Расширение (альтернативный сценарий)** | 1а. Недостаточно прав/доступа - система инициирует предоставление/расширение доступа либо фиксирует невозможность.  4а. При подготовке определения выявлены ошибки/неполнота - председатель корректирует проект и повторяет шаг 4. |

UC-004. Ознакомление судьи с определением председателя и меры по ускорению

|  |  |
| --- | --- |
| **№ шага процесса** | 11-15 |
| **Выполняемая задача** | Судья знакомится с определением председателя суда; при удовлетворении - принимает меры по ускорению рассмотрения дела. |
| **Цель** | Обеспечить исполнение результатов рассмотрения заявления: либо завершить процесс (отказ), либо реализовать меры по ускорению (удовлетворение). |
| **Роль (в соответствии со схемой)** | Судья |
| **Ожидаемый результат** | Судья ознакомлен с определением; при отказе процесс завершен; при удовлетворении приняты меры по ускорению и результат зафиксирован. |
| **Рекомендованная функциональность** | 1. Единая задача/входящее поручение судье на ознакомление с определением.  2. Быстрый переход из определения к материалам дела и связанным документам.  3. Фиксация исхода: «отказано» или «удовлетворено», и контроль исполнения мер по ускорению. |
| **Критичность** | Высокая |
| **Триггер** | Судье поставлена задача на ознакомление с определением. |
| **Предварительные условия** | Определение сформировано и связано с делом; судье предоставлен доступ; создана задача на ознакомление. |
| **Основной сценарий** | 1. Судья знакомится с определением председателя суда.  2. Судья определяет исход: удовлетворено заявление или отказано.  3. При отказе - судья фиксирует ознакомление, процесс завершается.  4. При удовлетворении - судья принимает меры к ускорению рассмотрения дела.  5. Судья фиксирует выполнение мер, процесс завершается. |
