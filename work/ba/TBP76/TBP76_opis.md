# [To be] ТБП76. Решить вопрос о раздельном рассмотрении требований

| **Наименование процесса** | ТБП76 — Решить вопрос о раздельном рассмотрении требований |
| --- | --- |
| **Суть процесса** | Процесс в TO BE описывает действия суда по определению необходимости раздельного рассмотрения заявленных требований с использованием Системы. Процесс начинается при возникновении необходимости разрешить вопрос о раздельном рассмотрении требований, после чего Система анализирует требования, а судья проверяет наличие нескольких самостоятельных требований и определяет целесообразность их раздельного рассмотрения. В ходе процесса судья выясняет мнение лиц, участвующих в деле, учитывает их возражения и проверяет, не приведет ли раздельное рассмотрение к нарушению прав участников процесса. Если имеются препятствия для раздельного рассмотрения, Система определяет лицо, заявившее соответствующее ходатайство, после чего суд разрешает вопрос об отказе и при необходимости принимает соответствующий судебный акт. При наличии оснований для раздельного рассмотрения судья фиксирует вопросы, подлежащие отдельному рассмотрению, порядок их рассмотрения, дату и время второго судебного заседания, после чего обеспечиваются назначение заседания и направление необходимых документов участникам. Процесс завершается фиксацией результата рассмотрения вопроса о раздельном рассмотрении требований либо отказом в таком рассмотрении. |
| **Участники процесса** | Судья; Канцелярия; Лицо, участвующее в деле (ЛУВД) |
| **НПА** | Арбитражный процессуальный кодекс Российской Федерации от 24.07.2002 N 95-ФЗ (ред. от 01.04.2025)  Постановление Пленума ВАС РФ от 25.12.2013 N 100 (ред. от 11.07.2014) "Об утверждении Инструкции по делопроизводству в арбитражных судах Российской Федерации (первой, апелляционной и кассационной инстанций)"  Информационное письмо Президиума ВАС РФ от 22.12.2005 N 99 (ред. от 01.07.2014) "Об отдельных вопросах практики применения Арбитражного процессуального кодекса Российской Федерации" |

**UC001 — Анализ требований и получение позиции участников**

| **№ шага процесса** | 0–13 |
| --- | --- |
| **Выполняемая задача** | Подготовить сведения о требованиях, определить дальнейшую процедуру и получить позицию лиц, участвующих в деле. |
| **Цель** | Обеспечить Судье структурированные сведения и позиции участников для решения вопроса о дальнейшем раздельном рассмотрении. |
| **Роль / Актор** | Судья; Лицо, участвующее в деле (ЛУВД) |

| **Рекомендуемая функциональность** | Автоматическая подготовка сведений о требованиях; отображение Судье результата анализа; фиксация позиции ЛУВД; сохранение пользовательских решений и маршрута. |

| **Триггер** | Судья начал рассмотрение вопроса о раздельном рассмотрении требований |

| **Основной сценарий** | 1. Система подготавливает сведения о требованиях для Судьи. 2. Судья проверяет состав требований и необходимость их раздельного рассмотрения. 3. Судья запрашивает позицию участников. 4. ЛУВД выражает позицию. |
| **Расширение (альтернативный сценарий)** | При наличии результата, ведущего к завершению на шаге 3, дальнейшее рассмотрение по этой ветви не выполняется. |
