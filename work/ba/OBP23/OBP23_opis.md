## ****3. Реестр UC****

**UC001 — Проверить работоспособность и самостоятельно устранить сбой**

|  |  |
| --- | --- |
| **№ шага процесса** | 0–7, 15–16 |
| **Выполняемая задача** | Проверка и мониторинг работоспособности каналов связи и сети «Интернет», выявление сбоя, определение его причины и самостоятельное устранение неисправности, если привлечение подрядчика не требуется. |
| **Цель** | Обеспечить своевременное выявление нарушений работоспособности каналов связи и сети «Интернет» и восстановить их работу собственными силами, когда это возможно. |
| **Роль/Актор (в соответствии со схемой)** | Основной актор: сотрудник отдела информатизации. Участник: Система. |
| **Ожидаемый результат** | Сбой не выявлен либо выявленная неисправность устранена сотрудником отдела информатизации; работоспособность каналов связи и сети «Интернет» обеспечена. |
| **Рекомендованная функциональность** | Автоматизированная регламентная проверка работоспособности каналов связи и сети «Интернет»; автоматизированный мониторинг; предоставление результатов проверки и мониторинга сотруднику отдела информатизации; учет поступивших заявок сотрудников судов при мониторинге. |
| **Критичность** | Необходимая. |
| **Триггер** | Возникла необходимость обеспечить или проверить работоспособность каналов связи и сети «Интернет». |
| **Предварительные условия** | Доступны каналы связи и средства мониторинга; сотрудник отдела информатизации имеет возможность проверить поступившие обращения сотрудников судов. |
| **Основной сценарий** | 1. Система выполняет регламентную проверку работоспособности каналов связи и сети «Интернет».  2. Сотрудник отдела информатизации проверяет наличие заявок сотрудников судов о перебоях в работе каналов связи или сети «Интернет».  3. Система выполняет мониторинг работоспособности с учетом имеющихся обращений.  4. По результатам мониторинга определяется наличие сбоя.  5. При обнаружении сбоя сотрудник отдела информатизации анализирует результаты проверки, мониторинга и технические сведения и устанавливает причину сбоя.  6. Сотрудник отдела информатизации определяет, требуется ли привлечение подрядчика.  7. Если подрядчик не требуется, сотрудник отдела информатизации самостоятельно устраняет сбой.  8. После устранения сбоя процесс завершается: работоспособность каналов связи и сети «Интернет» организована. |
| **Расширение (альтернативный сценарий)** | 4а. Сбой в работе сети «Интернет» не обнаружен.  4а.1 Дополнительные действия по устранению неисправности не выполняются.  4а.2 Процесс завершается: работоспособность каналов связи и сети «Интернет» организована.  6а. Для устранения сбоя требуется подрядчик.  6а.1 Процесс переходит к UC002 «Организовать устранение сбоя подрядчиком». |

**UC002 — Организовать устранение сбоя подрядчиком**

|  |  |
| --- | --- |
| **№ шага процесса** | 8–16 |
| **Выполняемая задача** | Подготовка и проверка запроса подрядчику, получение информации о выполненных работах, контрольная проверка работоспособности сети и повторное обращение при неустраненной неисправности. |
| **Цель** | Обеспечить устранение сбоя подрядчиком и подтвердить фактическое восстановление работоспособности каналов связи и сети «Интернет». |
| **Роль/Актор (в соответствии со схемой)** | Основной актор: сотрудник отдела информатизации. Участники: Система; Подрядчик. |
| **Ожидаемый результат** | Подрядчику направлен проверенный запрос, неисправность устранена и результат подтвержден контрольной проверкой; работоспособность каналов связи и сети «Интернет» обеспечена. |
| **Рекомендованная функциональность** | Автоматическое формирование драфта запроса подрядчику на основе технических логов; возможность проверки и корректировки драфта сотрудником отдела информатизации; поддержка повторной подготовки запроса при неустраненной неисправности. |
| **Критичность** | Необходимая. |
| **Триггер** | По результатам анализа сбоя установлено, что для его устранения требуется привлечение подрядчика. |
| **Предварительные условия** | Обнаружен сбой, установлена его причина и принято решение о необходимости привлечения подрядчика; Системе доступны технические логи для подготовки драфта запроса. |
| **Основной сценарий** | 1. Система автоматически формирует драфт запроса подрядчику с использованием доступных данных технических логов.  2. Сотрудник отдела информатизации проверяет подготовленный драфт и при необходимости корректирует его.  3. Сотрудник отдела информатизации направляет проверенный запрос подрядчику.  4. После выполнения работ сотрудник отдела информатизации получает от подрядчика информацию об устранении сбоя.  5. Сотрудник отдела информатизации выполняет контрольную проверку работоспособности сети «Интернет».  6. Если неисправность устранена, дальнейшие действия по восстановлению не требуются.  7. Процесс завершается: работоспособность каналов связи и сети «Интернет» организована. |
| **Расширение (альтернативный сценарий)** | 5а. Контрольная проверка показывает, что неисправность не устранена.  5а.1 Процесс возвращается к подготовке нового драфта запроса подрядчику.  5а.2 Система повторно формирует драфт запроса с использованием доступных технических логов.  5а.3 Сотрудник отдела информатизации проверяет и направляет повторный запрос подрядчику.  5а.4 После получения информации о выполненных работах сотрудник повторно проверяет работоспособность сети.  5а.5 Цикл повторяется до подтверждения устранения неисправности. |
