| Наименование процесса | ТБП61: Рассмотреть вопрос о разъединении дел |
| Суть процесса | Рассмотрение судьёй вопроса о разъединении соединённых ранее требований в отдельное производство в соответствии со статьёй 130 АПК РФ. Процесс включает автоматизированный анализ дела на предмет наличия оснований для разъединения (различие сторон, оснований иска, слабая связь требований), проверку подсудности выделяемых требований, возможное проведение судебного заседания и вынесение определения — либо о разъединении, либо об отказе в удовлетворении ходатайства. |
| Участники процесса | Судья, помощник судьи |
| НПА | "Арбитражный процессуальный кодекс Российской Федерации" от 24.07.2002 N 95-ФЗ  Постановление Пленума Верховного Суда РФ от 17.12.2024 N 40 "О некоторых вопросах, связанных с введением в действие Федерального закона от 29 мая 2024 года N 107-ФЗ "О внесении изменений в Федеральный закон "О несостоятельности (банкротстве)" и статью 223 Арбитражного процессуального кодекса Российской Федерации"  Постановление Пленума Верховного Суда РФ от 04.06.2024 N 12 "О подготовке дела к судебному разбирательству в арбитражном суде"  Постановление Пленума Верховного Суда РФ от 23.12.2021 N 46 "О применении Арбитражного процессуального кодекса Российской Федерации при рассмотрении дел в суде первой инстанции" |

3.Реестр UC (в части выполняемых пользователем задач и рекомендованной функциональности Системы)
UC-001: Проверка возможности рассмотрения судом вопроса о разъединении дел/ОС

|  |  |
| --- | --- |
| **Поле** | **Значение** |
| **№ шага процесса** | 0-9 |
| **Выполняемая задача** | Проверить процессуальную возможность рассмотрения судом вопроса о разъединении дел/обособленного спора (компетенция, стадия, наличие препятствий, достаточность материалов). |
| **Цель** | Обеспечить принятие вопроса к рассмотрению только при наличии процессуальных предпосылок и корректных входных данных. |
| **Роль (в соответствии со схемой)** | Судья |
| **Ожидаемый результат** | Зафиксирован вывод: "возможно рассмотреть" или "невозможно" (с указанием причины). Определён дальнейший маршрут: к судебному заседанию либо к выводу об отсутствии необходимости проводить судебное заседание/невозможности рассмотрения. |
| **Рекомендованная функциональность** | Чек-лист предпосылок (валидации), автоматический сбор данных по делу/ОС, подсказки по статусам/стадии, контроль комплектности материалов, журналирование выводов, уведомления и контроль SLA. |
| **Критичность** | Высокая |
| **Триггер** | Поступление заявления/ходатайства о разъединении либо инициирование вопроса судом. |
| **Предварительные условия** | Дело/ОС заведено в системе, доступны материалы и сведения о стадиях/участниках, у судьи есть доступ/полномочия. |
| **Основной сценарий** | 1. Система фиксирует событие (заявление/инициатива).  2. Помощник судьи и/или система открывают карточку дела/ОС и поднимают материалы.  3. Судья проверяет критерии возможности рассмотрения (стадия, отсутствие препятствий, достаточность данных).  4. Система сохраняет результат и предлагает следующий маршрут. |
| **Расширение (альтернативный сценарий)** | А1) Недостаточно материалов: система формирует задачу на доукомплектование, маршрут приостанавливается. А2) Выявлено препятствие: фиксируется причина, маршрут завершается/переходит к уведомлению. |

UC-002: Проведение судебного заседания по вопросу разъединения либо вывод об отсутствии необходимости СЗ

|  |  |
| --- | --- |
| **Поле** | **Значение** |
| **№ шага процесса** | 10-16 |
| **Выполняемая задача** | Назначить и провести судебное заседание по вопросу разъединения либо зафиксировать вывод, что проведение судебного заседания не требуется (в соответствии с принятым порядком). |
| **Цель** | Обеспечить надлежащее рассмотрение вопроса, соблюдение процессуальных прав участников и фиксацию результатов. |
| **Роль (в соответствии со схемой)** | Судья, Помощник судьи/Секретарь, Лица, участвующие в деле |
| **Ожидаемый результат** | Судебное заседание проведено и результаты зафиксированы (протокол/итоги), либо сформирован подтвержденный вывод "судебное заседание не требуется" с переходом к проверке оснований разъединения. |
| **Рекомендованная функциональность** | Календарь и подбор слотов, автоматической генерация извещений, рассылка уведомлений, регистрация явки, шаблон протокола, контроль сроков, трекинг доставки уведомлений. |
| **Критичность** | Высокая |
| **Триггер** | Результат проверки возможности рассмотрения: требуется судебное заседание либо принято решение, что оно не требуется. |
| **Предварительные условия** | Определен состав участников, доступны контактные данные и каналы уведомлений, определены дата/время и место/формат (если судебное заседание проводится). |
| **Основной сценарий** | 1. Судья принимает решение о необходимости судебного заседания.  2. Если судебное заседание требуется: помощник судьи и/или система подбирают слот, формируют и направляют извещения.  3. В день заседания фиксируется явка/неявка и ход заседания. 4) Система сохраняет итоги и обеспечивает переход к проверке оснований. |
| **Расширение (альтернативный сценарий)** | 1а. Судебное заседание не требуется: система фиксирует основание и переводит процесс к проверке оснований.  2а. Неявка участников: фиксируется неявка, судья принимает решение о возможности рассмотрения, при необходимости осуществляется перенос. |

UC-003: Проверка наличия оснований для разъединения дел/ОС

|  |  |
| --- | --- |
| **Поле** | **Значение** |
| **№ шага процесса** | 17-24 |
| **Выполняемая задача** | Оценить наличие оснований для разъединения: степень взаимосвязи требований, возможность самостоятельного рассмотрения, влияние на сроки и объем доказывания, иные значимые обстоятельства по материалам дела/ОС. |
| **Цель** | Сформировать обоснованный вывод для принятия решения: удовлетворить заявление о разъединении либо отказать. |
| **Роль (в соответствии со схемой)** | Судья, Помощник судьи |
| **Ожидаемый результат** | Сформирован вывод: "основания есть" либо "оснований нет", зафиксированы ключевые аргументы и ссылки на материалы дела/ОС, определена ветка процесса. |
| **Рекомендованная функциональность** | Подсветка релевантных материалов, поиск по документам, OCR для сканов, LLM-подсказки (резюме позиций сторон и фактов), чек-лист факторов, матрица "факт-документ", журналирование аргументации. |
| **Критичность** | Высокая |
| **Триггер** | Завершение стадии рассмотрения (проведено судебное заседание либо зафиксировано, что оно не требуется). |
| **Предварительные условия** | Материалы дела/ОС доступны и структурированы, заявление/доводы сторон доступны, результаты судебного заседания (если проводилось) зафиксированы. |
| **Основной сценарий** | 1. Система собирает материалы по вопросу разъединения.  2. Помощник судьи формирует подборку и при необходимости резюме.  3. Судья оценивает критерии и формирует вывод. 4) Система фиксирует результат и предлагает маршрут: отказ либо удовлетворение. |
| **Расширение (альтернативный сценарий)** | 1а. Данных недостаточно или имеются противоречия: судья инициирует дополнительные действия (истребование, перерыв, запрос объяснений), после чего проверка повторяется. |

| --- | --- |
| **Поле** | **Значение** |
| **№ шага процесса** | 25-33 |
| **Выполняемая задача** | Принять решение об отказе, подготовить и оформить судебный акт (определение), обеспечить направление участникам и фиксацию отправки/доставки. |
| **Цель** | Зафиксировать мотивированный отказ и обеспечить надлежащее уведомление участников. |

| **Рекомендованная функциональность** | Шаблоны определения, автозаполнение реквизитов, генерация пакета рассылки, интеграции с каналами отправки (ЛК, ЭДО, почта), контроль доставки, процессуальные сроки, уведомления о сроках, версионирование. |
| **Критичность** | Высокая |
| **Триггер** | Результат проверки оснований: "оснований нет". |
| **Предварительные условия** | Вывод об отсутствии оснований зафиксирован, определены адресаты и способы направления, доступны реквизиты дела/ОС. |
| **Основной сценарий** | 1. Судья выбирает ветку "Отказ".  2. Помощник судьи и/или система формируют проект определения по шаблону.  3. Судья утверждает и подписывает.  4. Система регистрирует документ, формирует рассылку и направляет участникам.  5. Фиксируются статусы отправки/доставки, ветка завершается. |
| **Расширение (альтернативный сценарий)** | 1а. Обнаружены ошибки в проекте: возврат на доработку.  2а. Доставка неуспешна: выполняется повторная отправка и/или смена канала, формируется задача помощнику судьи. |
