* 1. Реестр UC (в части выполняемых пользователем задач и рекомендованной функциональности Системы)

|  |  |
| --- | --- |
| **Поле** | **Значение** |
| **№ шага процесса** | 0–5 |
| **Выполняемая задача** | Инициировать подготовку к судебному заседанию по выбранному делу, автоматически проанализировать материалы дела, автоматически проанализировать документы, поступившие от сторон, сформировать рекомендацию по подготовке к делу, уведомить судью о готовности рекомендаций, передать результаты анализа в типовой процесс проверки выводов системы |
| **Цель** | Обеспечить судье возможность запустить подготовку к судебному заседанию и получить от системы понятные, структурированные рекомендации по дальнейшим процессуальным действиям на основе автоматического анализа дела и документов сторон, с последующей валидацией этих выводов судьёй |
| **Роль (в соответствии со схемой)** | Судья |
| **Ожидаемый результат** | Система по инициированию судьи выполнила автоматический анализ дела и документов, сформировала рекомендации по подготовке к судебному заседанию, уведомила судью о готовности результатов и передала их в типовой процесс «ТБП139. | **№ шага процесса** | 18–22 |
| **Выполняемая задача** | Перейти к типовому процессу «ТБП1.Проверить явку в СЗ»; определить, будет ли судебное заседание явочным; при не явочном формате завершить подготовку и перейти в ТБП68 «Провести СЗ» к шагу «Оформить протокол СЗ»; при явочном формате перейти к типовому процессу «ТБП56. Проверить график рассмотрения дела в зале СЗ»; завершить подготовку к СЗ с фиксацией формата проведения заседания |
| **Цель** | Обеспечить судье возможность до начала судебного заседания определить фактическую/заявленную явку участников и форму проведения заседания, а при необходимости проверить корректность планирования рассмотрения дела в конкретном зале судебного заседания, чтобы обеспечить организационно корректное проведение СЗ |
| **Роль (в соответствии со схемой)** | Судья |
| **Ожидаемый результат** | Судья выполнил предварительную проверку явки через ТБП1; определил, будет ли СЗ явочным; при не явочном формате подготовка к СЗ завершена с переходом в ТБП68 на шаг «Оформить протокол СЗ»; при явочном формате проверен график рассмотрения дела в зале СЗ через ТБП56 и зафиксировано, что СЗ будет проведено с участием сторон; сформировано завершающее событие (шаг 20 или 22) |
| **Рекомендованная функциональность** | Переход/интеграция с типовым процессом «ТБП1.Проверить явку в СЗ» (статусы явки, наличие ходатайств о рассмотрении в отсутствие, отметки по участникам); интерфейс фиксации решения «СЗ будет явочным/неявочным» (шаг 19) и сохранение основания; автоматический переход при неявке СЗ в «ТБП68.Провести СЗ» на шаг «Оформить протокол СЗ»; интеграция с типовым процессом «ТБП56. Проверить график рассмотрения дела в зале СЗ» с доступом к артефакту «График рассмотрения дела в зале СЗ»; журналирование действий судьи и статусов; разграничение прав доступа к сведениям о расписании и участниках |
| **Критичность** | Необходимая |
| **Триггер** | Судья завершает основные действия подготовки и переходит к проверке графика зала СЗ |
| **Предварительные условия** | Подготовка к СЗ находится на финальной стадии; судья авторизован и имеет доступ к карточке дела; доступен типовой процесс «ТБП1.Проверить явку в СЗ»; в системе имеются сведения о назначенном СЗ и участниках; при явочном формате доступен артефакт «График рассмотрения дела в зале СЗ» и типовой процесс «ТБП56.Проверить график рассмотрения дела в зале СЗ» |
| **Основной сценарий** | 1. На шаге 18 выполняется переход к типовому процессу «ТБП1.Проверить явку в СЗ», в рамках которого анализируется наличие ходатайств о рассмотрении дела в отсутствие представителя и фактическая явка участников. 2. На шаге 19 выполняется развилка «СЗ будет явочным?». 3. Если Нет, выполняется шаг 20 подготовка к СЗ завершена, СЗ будет проведено без участия сторон, осуществляется переход в ТБП68.Провести СЗ к шагу «Оформить протокол СЗ». 4. Если Да, выполняется шаг 21 переход к типовому процессу ТБП56.Проверить график рассмотрения дела в зале СЗ, где проверяется корректность данных в графике судебных заседаний и при необходимости вносятся изменения. 5. После завершения ТБП56.Проверить график рассмотрения дела в зале СЗ выполняется шаг 22 подготовка к СЗ завершена, СЗ будет проведено с участием сторон (фиксируется результат и готовность к проведению заседания). |
| **Расширение (альтернативный сценарий)** | 1а. Недостаточно данных для определения явки. Судья фиксирует, что сведения о явке/ходатайствах отсутствуют или противоречивы; решение по шагу 19 принимается на основе доступных отметок ТБП1.Проверить явку в СЗ, при необходимости с последующей корректировкой статуса (в рамках организационных действий). 4а. Конфликт/ошибка в графике зала СЗ. В рамках ТБП56.Проверить график рассмотрения дела в зале СЗ выявляется пересечение по времени/зал недоступен/некорректные данные; судья вносит изменения в график либо фиксирует необходимость переноса/корректировки расписания, после чего процесс продолжается к шагу 22. 5а. Ошибка выполнения/недоступность ТБП1.Проверить явку в СЗ. Система фиксирует технический сбой, предоставляет судье возможность повторить переход; при невозможности судья выполняет проверку явки вручную на основе доступных данных, с последующей фиксацией результата в системе. |
