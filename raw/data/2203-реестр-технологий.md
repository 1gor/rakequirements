### Реестр технологий, на основе которых создается Система

Выбор технологического стека для создания Системы обусловлен стратегическими целями проекта и нефункциональными требованиями, в частности, требованиями к импортозамещению, отказоустойчивости, масштабируемости и отсутствию зависимости от конкретных коммерческих поставщиков (*vendor lock-in*). Приоритет отдавался зрелым технологиям с открытым исходным кодом, распространяемым под пермиссивными лицензиями (такими как Apache 2.0, MIT), которые не налагают вирусных («copyleft») ограничений и не требуют приобретения коммерческих лицензий на использование.

Стек технологий Системы логически разделен на несколько уровней, соответствующих архитектурным слоям: Ядро Платформы, Прикладной уровень, Клиентский уровень и уровень интеграций.

#### Технологии Ядра Платформы

Компоненты Ядра Платформы обеспечивают централизованные, общесистемные функции и служат технологическим фундаментом для всей Системы.

| Назначение | Технология |
| :--- | :--- |
| Распределенная шина данных | **Apache Kafka** |
| СУБД для аудиторного журнала | **PostgreSQL** |
| Управление идентификацией и доступом | **Keycloak** |
| Маршрутизация и обработка данных | **Benthos** |
| Реестр схем данных | **Apicurio Registry** |
| Объектное хранилище (S3-совместимое) | **MinIO** (или аналоги) |
| Сервис криптографических операций (УКЭП) | Централизованный API в соответствии с 63-ФЗ |

#### Технологии Прикладного уровня

На этом уровне реализуется бизнес-логика Ограниченных контекстов (бизнес-доменов) Системы.

| Назначение | Технология |
| :--- | :--- |
| Среда исполнения и язык программирования | **.NET (C#)** |
| Хранение данных бизнес-доменов | **PostgreSQL** |
| Внутренний обмен сообщениями (для проекторов) | **RabbitMQ** |

#### Технологии Клиентской части (Frontend)

Архитектура Системы предполагает разделение серверной логики (backend) и клиентского приложения (frontend) для реализации в виде одностраничного приложения (Single Page Application, SPA).

| Назначение | Технология |
| :--- | :--- |
| Пользовательский интерфейс | **SPA** ( React или аналоги) |

#### Интеграционные технологии

| Назначение | Технология |
| :--- | :--- |
| API-шлюз (взаимодействие "запрос-ответ") | **OpenAPI 3.0** |
| Прямая интеграция с шиной данных | Адаптеры **Apache Kafka** |

#### Контейнеризация и оркестрация

| Назначение | Технология |
| :--- | :--- |
| Упаковки приложений и их зависимостей в изолированные контейнеры | **Docker** |
| Автоматическое развертывание, масштабирование и управление контейнеризированными приложениями, обеспечивающее отказоустойчивость и эффективное использование ресурсов | **Kubernetes** |

#### Комплекс средств для обеспечения наблюдаемости (Observability)

| Назначение                                                                        | Технология                   |
|:----------------------------------------------------------------------------------|:-----------------------------|
| Сбор и хранение метрик производительности всех компонентов системы.               | **Prometheus**               |
| Визуализация метрик и создания панелей мониторинга (dashboards)                   | **Grafana**                  |
| Централизованный сбор, обработка и пересылка логов                                | **Fluentd** или **Logstash** |
| Индексация и хранение логов с возможностью полнотекстового поиска                 | **OpenSearch** или **Loki**   |
| Распределенная трассировка команд и событий на всех этапах распределённой системы | **OpenTelemetry** (сбор) и **Jaeger** (хранение и визуализация)                             | 

#### Инфраструктура и CI/CD (непрерывные интеграция и развертывание)

| Назначение                                                                                                | Технология                                |
|:----------------------------------------------------------------------------------------------------------|:------------------------------------------|
| Автоматизация сборки, тестирования и развертывания приложений в среде Kubernetes                          | **GitLab CI/CD**, **Jenkins** или аналоги |
| Декларативное описание и управление всеми инфраструктурными ресурсами (серверами, сетями, базами данных). | **OpenTofu** (Terraform fork)             |
| Управление маршрутизацией и безопасностью API в Kubernetes с поддержкой стандарта Gateway API             | **Kong** или **Traefik**                  |
