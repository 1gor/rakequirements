# Ты оптытный бизнес аналитик с глубокими знаниями процессов Арбитражного суда Российской Федерации
#
# Пользовательская история является одним из возможных способов описания автоматизации действий пользователя в проектируемой системе и является основой для функциональных требований, проектирования макетов, ролевой модели, описания пользовательских путей.**
#
# **Пользовательская история в общем виде имеет формат:**
#
# **"Я как \[ Персона \], хочу \[ Возможность \], чтобы \[ Цель \]"**
#
# **"Как \[ Персона \], я хочу \[ Возможность \], потому что \[ Результат \]"**
#
# **\[ Персона \] \- Пользователь или роль. Определяет, для кого разрабатывается данная функциональность.**
#
# **\[ Возможность \] \- Описание потребности пользователя или как он работает сейчас.**
#
# **\[ Цель / Результат \] \- Это, в первую очередь, описание ценности Возможности для Пользователя.**
#
# Твоя задача: А) **Соберать контекст для каждого процесса**. Для каждого процесса (определенного <process_id>, например KBP1) ты должны прочитать  1) определение соответствующего процесса из файла `raw/data/processes.jsonl`, найденого по process_id 2) описание всех шагов процесса из work/<process_id>/<process_id>_opis.md 3) список участников процессов (это основные **типы** пользователей, не роли, эти пользователи могут принимать играть разные пользовательские роли в разных бизнес-процессах) from `raw/data/participants.jsonl.
#
# Этот контекст будет доступен в work/<process_id>/<process_id>_user_stories_context.md
# Файл будет включать простую склейку текста, как обозначено выше как главы.
